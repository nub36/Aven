# Aven Natural Voice на VPS — Silero Aigul (этап 6)

**Голос выбран: Silero v5 CIS (MIT) `ru_aigul` — Natural Voice Female Aven** (решение владельца
по итогам этапа 5). Этот документ — как довести его до рабочего голоса Aven на **вашем** VPS
(Ubuntu 24.04, 1 CPU, 2 ГБ RAM, 15 ГБ NVMe, без GPU), без оплаты за запросы и внешних API.

**На реальный VPS агент ничего не ставит** (доступа нет) — ниже пошаговая инструкция.
Ничего из перечисленного не изображает уже выполненным: живой прогон сервера с Silero
сделан в CI (`.github/workflows/silero-aigul-live.yml`, результаты — `review/silero-aigul-live/`),
deploy на VPS — за владельцем по этим шагам.

Архитектура (docs/TTS_RESEARCH.md §19):

```
Aven Web (GitHub Pages, HTTPS)
   → NaturalTTSProviderExperimental (prototype/js/tts/providers.js)
   → HTTPS endpoint на вашем VPS (Caddy, ваш домен)
   → research/tts/server.py 0.4.0 (production-like; Silero в памяти с первого старта)
   → audio/wav → браузер → Female Aven говорит голосом Aigul
   ⤷ fallback: системный speechSynthesis — ВСЕГДА доступен (System TTS не удалён)
```

## Защита endpoint (уже в коде, настраивается в `/etc/aven-tts.env`)

| Механизм | Значение по умолчанию (deploy-скрипт) |
|---|---|
| CORS | только `https://nub36.github.io` + localhost (dev); другое — `AVEN_TTS_ORIGINS` |
| Rate limit | 12 синтезов/60 с на IP → `429` + `Retry-After` (`AVEN_TTS_RATE_N/_WINDOW_S`) |
| Длина текста | 600 символов → `413`; тело запроса > 20 КБ → `413` |
| Методы | только `GET`/`POST`/`OPTIONS`; `PUT/DELETE/PATCH` → `405` + `Allow` |
| Health | minimal: `ok/status/server/version/max_chars/default_voice`, без лишнего |
| Приватность | текст запроса не логируется и не пишется на диск; управляющие символы вырезаются |
| Секреты | их нет: публичный Pages → публичный HTTPS endpoint; ключей в JS нет |
| systemd | автозапуск, `Restart=on-failure`, `MemoryMax=1500M`, hardening |

# Инструкция для владельца (Windows, пошагово)

Всё, что нужно делать на VPS, — копировать команды из шага 5. Ничего разбирать
самостоятельно не нужно; если что-то идёт не так — пришлите вывод команды, дальше решаем вместе.

## 1. Что открыть в панели VPS

Откройте в браузере панель управления вашим VPS (адрес панели и логин — из письма
хостинга при покупке VPS). Найдите раздел с информацией о сервере (обычно «Серверы» /
«Мои серверы» → ваш сервер).

## 2. Какие данные найти

Запишите три вещи из панели:

1. **IP-адрес VPS** — например `203.0.113.10` (IPv4).
2. **Логин** — обычно `root` (или другой пользователь с правами sudo).
3. **Пароль** (или ключ, если задавали при создании).

Там же обычно видно имя сервера и ОС — нужна **Ubuntu 24.04** (если другая — напишите,
шаги чуть изменятся).

## 3. Нужен ли DNS record (A-запись)

Браузер на GitHub Pages не может обращаться к «голому» IP по HTTPS (сертификат
Let's Encrypt выдаётся только на домен). **Новый домен покупать не нужно**, если у вас
уже есть любой домен — достаточно поддомена:

- В панели управления доменом (там, где вы покупали домен, раздел «DNS» / «Управление зоной»)
  создайте **A-запись**: имя `tts` (получится `tts.ваш-домен.ru`), тип `A`, значение —
  IP вашего VPS из шага 2, TTL по умолчанию.
- Если домена нет совсем и покупать не хотите — напишите; вариант «только для себя»
  возможен через локальный HTTP-доступ, но публичный Pages→VPS требует домен.

DNS обновляется до нескольких минут–часов; проверить можно там же в панели (запись «активна»).

## 4. Как подключиться к серверу

На Windows: откройте **PowerShell** (Пуск → наберите «PowerShell») и введите:

```
ssh root@IP_ВАШЕГО_VPS
```

(замените `IP_ВАШЕГО_VPS` на IP из шага 2; на вопрос про отпечаток — `yes`; затем пароль).
Если SSH ругается на «connection refused» — в панели VPS откройте порт 22 или используйте
консоль VNC-консоль из панели хостинга (кнопка «Консоль») — команды те же.

## 5. Какие команды вставить

В окно SSH (после входа) — по одной, дожидаясь окончания каждой:

```
apt-get update -qq
git clone --depth 1 https://github.com/nub36/Aven.git
cd Aven/research/tts/runtime/vps
sudo ./deploy-vps.sh silero
```

Скрипт сам поставит всё необходимое (~5–10 минут; Silero ≈ 700 МБ диска: torch CPU + модель),
создаст systemd-сервис `aven-tts` (Silero загружается в память **один раз при старте**
сервиса и живёт между запросами; автозапуск при перезагрузке VPS; перезапуск при падении)
и в конце покажет health-check и синтез тестовой фразы (файл `/tmp/aigul-check.wav` на VPS).

Затем HTTPS (Caddy берёт и продлевает сертификат Let's Encrypt автоматически; `tts.ваш-домен.ru`
— из шага 3):

```
sudo apt install -y caddy
sudo tee /etc/caddy/Caddyfile >/dev/null <<'EOF'
tts.ваш-домен.ru {
    reverse_proxy 127.0.0.1:8080
}
EOF
sudo systemctl reload caddy
```

Всё. Сервер слушает только 127.0.0.1:8080 — наружу его публикует Caddy по HTTPS.

**Обновление кода Aven** (когда примут PR этапа 6 и захотите обновиться):
`sudo AVEN_REF=main ./deploy-vps.sh silero` — скрипт подтянет свежий код и перезапустит сервис.
**Откат**: `sudo AVEN_REF=<SHA-коммита> ./deploy-vps.sh silero` (SHA — из истории GitHub).

## 6. Как проверить HTTPS health

На вашем компьютере (Windows), в браузере или PowerShell:

```
curl https://tts.ваш-домен.ru/api/tts/health
```

Должно вернуться (минимум сведений о сервере — так задумано):

```json
{"ok": true, "status": "ok", "server": "aven-tts-research", "version": "0.4.0", "max_chars": 600, "default_voice": "silero_cis_mit/ru_aigul"}
```

Если сертификат ещё не готов — подождите 1–2 минуты и повторите (Caddy получает его
при первом обращении). На самом VPS: `systemctl status aven-tts --no-pager`.

## 7. Как подключить URL в Aven

Откройте Aven (GitHub Pages) → **Настройки → Голос**:

1. «Движок речи» → **Natural Voice (Silero · свой сервер)**.
2. «Self-hosted TTS-сервер» → впишите `https://tts.ваш-домен.ru` → кнопка **«Проверить»**.
3. Статус должен стать: **«подключён · aven-tts-research 0.4.0 · голосов: 1 · … мс»**.
4. «Голос» → **Aigul · Silero CIS** (подставится сам из `default_voice` сервера).

Системный голос остаётся запасным вариантом всегда: если сервер недоступен — Aven честно
сообщит тостом «Natural Voice недоступен … — используется системный голос» и скажет
системным голосом.

## 8. Как произнести новую тестовую фразу

Там же в Настройках → Голос → кнопка **«▶ Прослушать»**: для Natural Voice она отправляет
на сервер тестовую фразу владельца —

> «Авен проверяет натуральный голос. Сейчас 18 часов 43 минуты, пробег автомобиля 104520 километров.»

Это НЕ готовый MP3: текст уходит на ваш VPS, Silero синтезирует его заново, браузер
воспроизводит полученный WAV. Любая другая новая фраза — так же (например, спросите Aven
на Главной «Что у меня сегодня?» или «Какой пробег?» — ответ озвучится Natural Voice,
если включены голосовые ответы).

## 9. Как убедиться, что говорит Silero Aigul, а не System TTS

Четыре независимые проверки:

1. **Тост/лейбл**: при воспроизведении статус Aven показывает «Говорю · Natural» (не
   «системный голос»), и нет тоста про fallback.
2. **«Последний запуск»** в Настройках → Голос: источник = `self-hosted сервер`
   (не `speechSynthesis`, не «готовый образец»), с задержкой в миллисекундах.
3. **На VPS виден запрос** (шаг 4–5): `sudo journalctl -u aven-tts -n 5` — последняя строка
   вида `[tts] silero_cis_mit/ru_aigul chars=… synth=0.08s` появляется в момент нажатия
   «Прослушать». Сам текст фразы в лог НЕ пишется (приватность) — только длина и время.
4. **На слух**: Aigul — нейроголос, заметно отличается от системного Windows-голоса;
   MP3 живого прогона тех же фраз из CI лежат в репозитории: `review/silero-aigul-live/mp3/`
   (можно открыть на GitHub и сравнить один в один).

## Честные ограничения

- Исследовательский runtime: 1 одновременный пользователь; синтез на 1 CPU сериализован
  (второй запрос ждёт до 20 с, затем честный `503`), rate limit 12/60 с на IP.
- Сервер отдаёт PCM WAV (без перекодирования в MP3) — на LAN/мобильном интернете этого
  достаточно; MP3/Opus на стороне VPS — отдельный будущий шаг (ffmpeg).
- Липсинк: тайминги/виземы этот API не отдаёт — так и задумано (docs/TTS_RESEARCH.md §19):
  lip-sync — отдельный будущий слой (Silero-аудио → анализ → виземы → 3D Female Aven).
- 3D-модель этапа 5 не переделывалась и с этим этапом не связана.

## Откат / удаление

```
sudo systemctl disable --now aven-tts
sudo rm /etc/systemd/system/aven-tts.service /etc/aven-tts.env
sudo rm -rf /opt/aven-tts            # Silero-модель и venv
sudo apt remove -y caddy && sudo rm /etc/caddy       # если Caddy больше не нужен
```
