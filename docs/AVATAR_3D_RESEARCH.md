# AVATAR_3D_RESEARCH — 3D Female Aven: исследование и честный статус (этап 5)

> Дата: 2026-09-26. Задача владельца: **бюст Female Aven** (голова + полная шея + плечи/верх груди,
> БЕЗ полного тела) по утверждённому reference
> (`prototype/assets/character/master/female-aven-reference.jpg`), GLB/GLTF realtime-friendly
> для браузера, с состояниями и (в идеале) лицевым ригом. **Identity важнее факта 3D**: если
> инструменты дают «другую девушку» — модель НЕ называется Female Aven, фиксируется честный
> вывод и следующий шаг.

## 0. Ключевой итог (коротко)

- Сделан полностью бесплатный CPU-пайплайн **TripoSR → bake-texture → децимация → GLB → Three.js
  viewer** (workflow `Avatar 3D Research`, ручной; ничего не коммитит в ветку автоматически).
- Результат — **экспериментальная автоматическая реконструкция**, а не финальная Female Aven:
  у неё **нет rig/blendshapes, отдельных глаз, век и челюсти** — single-image-to-3D это не даёт
  в принципе. Viewer (`prototype/aven-3d.html`) честно помечает модель как эксперимент и
  показывает рядом reference для оценки сходства.
- **Сходство лица оценивает только владелец** (у агента нет vision): по 30 рендерам + видео-облёту
  в артефакте `avatar-3d-renders` и в самом viewer'е.
- Главная страница и PNG-персонаж **не изменены**; Character Off работает как раньше; 3D —
  отдельная страница-исследование.

## 1. Что исследовано и выбрано

| Инструмент | Что даёт | Почему выбран/отвергнут |
|---|---|---|
| **TripoSR** (VAST-AI, MIT) | single-image → 3D меш, CPU-режим, UV+текстура | **Выбран**: бесплатный, offline, работает на CPU-раннере, воспроизводим пиннингом коммита |
| InstantMesh, CRM, LGM | image-to-3D, лучшие детали | GPU-раннеры/сложнее сборка; не проходят ограничение «без GPU cloud» этапа |
| Hunyuan3D / Tripo API / Rodin / Meshy | облачные, качество выше | платные тарифы/облако — запрещено этапом; не используются |
| Face reconstruction (DECA/EMOCA/SMIRK) | точная геометрия лица + AU | только лицо (без причёски/плеч), сложная интеграция, лицензии аккуратнее; отмечено как следующий шаг |
| Blender (ручной) | всё: риг, blendshapes, sculpt по reference | не автоматизируется агентом в этом окружении; путь владельца/художника для финала |
| 3D-художник | финальное качество | явная опция «B» из задачи, если автоматика не сохранит сходство |

Пиннинги (воспроизводимость): TripoSR `107cefd`, torchmcubes `879926d` (обязателен
`pip install --no-build-isolation` против установленного torch — иначе сборка падает),
torch CPU с download.pytorch.org/whl/cpu, trimesh>=4.4 (на 4.0.5 падает на numpy 2.x),
rembg[cpu] (без extra не ставится onnxruntime), moderngl 5.10 + libegl/libgl/mesa для
headless bake-texture.

## 2. Пайплайн (workflow `.github/workflows/avatar-3d-research.yml`)

1. Входы: **master reference** (утверждённое лицо) и **transparent PNG** (запасной вход) — оба
   образа уже в репозитории; фон убирает rembg (u2net, ~170 МБ скачивается раннером).
2. TripoSR `run.py --device cpu --bake-texture --texture-resolution 2048 --mc-resolution 256 --render`:
   xatlas UV-атлас + запечённая текстура 2048, 30 рендеров вокруг модели + mp4 (рендер самой
   модели, без GL) — по ним владелец судит о форме со всех сторон.
3. `research/3d/postprocess_bust.py`: OBJ+texture → децимация до ~120k треугольников
   (fast-simplification), **UV переопроектируются на исходные вершины через cKDTree** (децимация
   теряет UV — проверено локально, иначе GLB выходил без текстуры), нормали, центрирование
   (высота 1.6, основание y=0), экспорт GLB с встроенной текстурой + `stats.json`.
4. Артефакты: `avatar-3d-glb` (GLB обоих входов + stats), `avatar-3d-renders` (input.png,
   30 рендеров, mp4, obj, texture), `avatar-3d-logs` (retention 14 дней).
5. Publish-джоб ботом `github-actions[bot]` кладёт компактный набор в ветку: GLB + stats +
   turntable.mp4 → `prototype/assets/3d/`, 6 рендеров + input + texture → `review/3d-aven-bust/`
   (mesh.obj десятки МБ — только в артефакте). Причина: артефакты Actions лежат в Azure blob,
   недоступном из песочницы агента; публикация в ветку — устоявшийся паттерн tts-research.yml.

Запуск: изменить `.github/triggers/avatar-3d.txt` в ветке этапа (или Actions → Run workflow
после попадания на main).

## 3. Viewer PoC — `prototype/aven-3d.html`

Отдельная страница (Three.js 0.180 vendored, MIT, `prototype/assets/vendor/three/`). Главная и
PNG-персонаж не затрагиваются.

Реализовано честно:

- загрузка GLB, автокадрирование, OrbitControls (мягкое вращение мышью);
- состояния **idle / listening / thinking / speaking / success / important / waiting / error**
  со спокойной процедурной анимацией (дыхание ~0,35% масштаба, микродвижения головы суммой
  синусов, лёгкие наклоны по состоянию, one-shot кивок/поворот для success/error);
- авто-детекция blendshapes (blinkLeft/blinkRight/jawOpen/smile/brows): если будущая модель их
  имеет — автоматически включаются моргание, челюсть, улыбка; для текущей экспериментальной
  модели панель возможностей честно показывает «модель без blendshapes»;
- **«уровень 0» lip-sync**: амплитуда звука (Web Audio AnalyserNode) → речевая активность;
  с jawOpen — движение губ, без него (текущая модель) — микрокивки;
- озвучка демо: существующие сэмплы vd17 (тот же звуковой эталон);
- PNG-fallback: если GLB не загрузился — честное сообщение + `female-aven-transparent.png`
  (тот же образ, что на Главной; ничего не подменяется).

Не реализовано (и не обещается в этом PoC): rig-анимация скелета, ARKit-blendshapes,
фофемно-точный lip-sync (см. §6), отдельные глаза/веки, волосы как отдельный меш.

## 4. Ограничения автоматического подхода (почему это НЕ финальная Female Aven)

1. Single-image-to-3D реконструирует форму «на глаз» модели: невидимые части (затылок, макушка,
   плечи сзади) — правдоподобная реконструкция, а не утверждённая внешность.
2. Нет лицевого рига: моргание, губы, мимика недоступны как morphs — состояние speaking
   компенсируется движением головы (и честно подписано в UI).
3. Текстура запекается из одного фото: затылок/боковые части будут «дорисованы» моделью.
4. Сходство лица — решение владельца; агент не имеет vision и не оценивает его.

## 5. Статус результата: A или B

- **Вариант A** (GLB достаточно похож): владелец подтверждает сходство по рендерам/облёту →
  GLB + viewer остаются как экспериментальный 3D-этап, дальше улучшается руками (см. §6).
- **Вариант B** (непохоже): модель НЕ называется Female Aven. Зафиксированные следующие шаги:
  1. Blender: ручной sculpt/ретопо по reference + готовый female-base mesh с ригом/blendshapes
     (бесплатные CC0/CC-BY базы, например MetaHuman-подобные community-риги), текстура
     проецируется с reference-фото;
  2. дополнительные reference-виды (профиль, 3/4) от владельца → TripoSR multi-view не умеет,
     но пригодятся художнику/для фотограмметрии;
  3. внешний image-to-3D (платные сервисы) — только с явного решения владельца;
  4. 3D-художник — максимальное сохранение identity.

## 6. Путь к полноценному ригу и lip-sync (следующие уровни)

- **Риг/blendshapes**: ручная работа в Blender (ARKit-набор ~52 morphs — стандарт для
  совместимости). Автоматически из фото — не существует в бесплатном offline.
- **Viseme timings**: TTS timings не выдаёт ни один из отобранных движков (не блокер):
  уровень 0 (амплитуда) уже в viewer; уровень 1 — G2P ru из текста (фонемы → visemes);
  уровень 2 — Rhubarb-WASM / MFA по аудио. Подробнее — TTS_RESEARCH.md §14.

## 7. Как проверить владельцу (Windows, пошагово)

1. Скачать артефакт `avatar-3d-renders` со страницы Actions → прогон «Avatar 3D Research»
   (кнопка Artifacts внизу): распаковать ZIP, открыть `0/render.mp4` — облёт реконструкции;
   рядом `0/render_*.png` — все 30 видов, `master`-вариант = по утверждённому reference.
2. Открыть страницу прототипа → `aven-3d.html` (после merge ветки) — покрутить модель мышью,
   нажать «Авто-демо состояний», включить озвучку speaking.
3. Сравнить лицо с reference (он же показан на странице) и ответить: похоже / не похоже.
   Это и есть решение A/B из §5.

## 8. Известные проблемы/особенности

- **Привязка текстуры (исправлено):** `xatlas.export()` пишет OBJ с UV, но без `map_Kd` в MTL →
  trimesh подставлял placeholder 2×2 px (прогон 36229047288: stats `texture (2,2) px`).
  `postprocess_bust.py` теперь читает `texture.png` из каталога OBJ явно (проверено локально на
  репро и финальным прогоном 36231486547: 2048×2048 в GLB).
- Децимация переопроектирует UV «ближайшей вершиной»: на границах UV-островов возможны
  лёгкие смешения цвета (в stats.json: `uv: reprojected…`); если меш ≤ 120k — UV родные.
- rembg может оставить/убрать лишнее на волосах — влияет на форму reconstruction.
- GLB ~5 МБ (меш ~120k + текстура 2048) — приемлемо для страницы прототипа.
- Рендеры TripoSR 256×256 и turntable ~23 КБ (низкий битрейт 30 кадров) — достаточны для
  оценки силуэта; детальнее — сам GLB в viewer'е.
- Меш не watertight (открытое основание бюста) — ожидаемо для бюста, не ошибка.

## Исправление viewer, часть 2 (2026-09-26, новая сессия) — настоящая причина

После правки выше (`BufferGeometryUtils.js`) страница **всё ещё** показывала «GLB недоступен»
на реальном Android Chrome. Разбор полного module graph (не по старым отчётам, а заново, с
проверкой каждого публичного URL) нашёл ВТОРОЙ, более фундаментальный дефект, который правка
выше не покрывала:

- Начиная с three.js r150 минифицированная сборка **разделена на два файла**:
  `three.module.min.js` (маленький реэкспорт) реально содержит
  `import{...}from"./three.core.min.js"` — весь код библиотеки лежит именно в
  `three.core.min.js`, подключаемом ОТНОСИТЕЛЬНЫМ путём (importmap на него не влияет).
- В репозитории был провендорен только `three.module.min.js`; `three.core.min.js` **никогда
  не коммитился** (проверено `git log --all` — файла нет ни в одной ревизии).
- Публичный URL `https://nub36.github.io/Aven/assets/vendor/three/three.core.min.js` отдавал
  честный 404 GitHub Pages («File not found»), поэтому сам импорт `'three'` падал ещё до
  выполнения `js/aven3d.js` — GLTFLoader/OrbitControls/сцена вообще не создавались.
- Побочно (не основная причина, самоустранилось за время сессии): в момент первой проверки
  `assets/vendor/three/utils/BufferGeometryUtils.js` тоже на короткое время отдавал 404 при
  прямом запросе без cache-bust, хотя файл существует в репозитории и в дереве последнего
  коммита — похоже на краткое отставание кэша CDN GitHub Pages (Fastly) от нового деплоя;
  повторная проверка через несколько минут без каких-либо изменений в репозитории уже
  показывала 200. Файл не трогался — доказанной причины «отсутствует» для него нет.

### Что сделано

- Довендорен `prototype/assets/vendor/three/three.core.min.js` — байт-в-байт из официального
  npm-пакета `three@0.180.0` (`build/three.core.min.js`); совпадение SHA-256 с содержимым
  тарболла проверено (`registry.npmjs.org/three/-/three-0.180.0.tgz`, sha1 тарболла сверен
  с `dist.shasum` из `registry.npmjs.org/three/0.180.0`). Уже вендоренные
  `three.module.min.js`, `GLTFLoader.js`, `OrbitControls.js`, `BufferGeometryUtils.js`
  сверены тем же способом — побайтово идентичны официальным файлам three@0.180.0.
- `prototype/js/aven3d.js` и `prototype/aven-3d.html`: расширена диагностика
  `window.__aven3d` — теперь всегда объект (базовый каркas ставится инлайн-скриптом ДО
  модуля) с полями `moduleLoaded`, `rendererCreated`, `glbLoaded`, `meshCount` (плюс прежние
  `status/meshes/triangles/vertices/morphs/error`), обновляемыми по мере реального
  прохождения этапов — снаружи объективно видно, где именно остановилась загрузка.
- Комментарий в `aven-3d.html` рядом с importmap объясняет разделение
  `three.module.min.js` / `three.core.min.js`, чтобы дефект не повторился при будущем

## Исправление viewer, часть 3 (2026-09-26, сессия XXVI) — ориентация, камера, свет

После части 2 GLB реально загружался и рендерился на реальном Android, но viewer был
непригоден для объективной оценки: бюст «лежал на боку», лицо было очень тёмным,
удобных ракурсов (фронт/профили/затылок) не было. Найденные объективные причины
(по данным самого GLB, не по догадкам):

### Причина 1: система координат GLB — Z-up (бюст «лежал»)

GLB экспортирован `trimesh` (см. `asset.generator` в JSON-чанке) из пайплайна TripoSR
в **Z-up** системе: макушка = **+Z**, лицо = **+X**, сырой bbox X ±0.469 / Y 0…1.6 /
Z ±0.819 (вертикальная ось — Z, extent 1.639 — максимальный). three.js — **Y-up** мир,
поэтому без коррекции бюст лежал (поворот ≈90°). Проверено программным CPU-рендером
(перспективная растеризация с z-buffer и текстурой, без WebGL) всех 6 осевых видов
сырого меша: вид с +Z — макушка, с +X — лицо, с ±Y — профили.

**Исправление (GLB не тронут, sha256 зафиксирован тестом):** в `js/aven3d.js` gltf-сцена
обёрнута в группу `orient` с кватернионом `ORIENT_FIX = RotY(−90°)·RotX(−90°)`
(эквивалент перестановки осей `(x,y,z) → (y,z,x)`): макушка +Z → +Y (вверх),
лицо +X → +Z (к зрителю). Нормализация (высота 1.6, низ y=0, центр X/Z) выполняется
по bounding box **после** поворота. Структура: `modelRoot` (анимация состояний) →
`orient` (ориентация+нормализация) → `gltf.scene` (нетронутый GLB).

### Причина 2: материал GLB затемнял лицо (двойной дефект экспорта)

В JSON-чанке GLB у единственного материала:

1. `baseColorFactor = [0.4, 0.4, 0.4, 1]` — по спецификации glTF факторы **умножаются**
   на текстуру → вся текстура (включая кожу) затемнялась в 2.5 раза;
2. `metallicFactor` **отсутствует** → по спецификации glTF default = **1.0** (полный
   металл); металл без environment map в three.js отражает почти ничего → чёрный вид.

**Исправление (presentation-фикс в viewer, файл GLB и текстура не меняются):** после
загрузки у материалов `color → белый`, `metalness → 0`, roughness ≥ 0.6.

### Свет, фон, камера (оценочный viewer)

- **Свет** — нейтральный studio без цветного glow: key DirectionalLight 0xffffff 2.3 из
  (0.9, 1.9, 2.6) (спереди-сверху), fill 0xffffff 1.0 из (−1.8, 1.1, 1.8), слабый rim
  0xe8eeff 1.3 из (0.3, 2.2, −2.4) (отделяет тёмные волосы от фона), hemisphere
  0xffffff/0x8a8f99 0.95 (тени не проваливаются в чёрное). Прежний тёмно-синий
  фон/синий rim убраны.
- **Фон** — нейтральный светло-серый градиент (CSS): тёмные волосы и одежда читаются.
- **Начальная камера** — пресет «Спереди»: строго анфас, вся голова + шея + плечи по
  центру. Дистанция считается из bounding box: `fitDistance = max(полувысота/tg(fov/2),
  полуширина/(tg(fov/2)·aspect)) · 1.15` — модель целиком в кадре и на портретном
  телефоне, и на десктопе; при resize/повороте экрана активный пресет пересчитывается.
- **Пресеты** — Спереди/Слева/Справа/Сзади/Сброс вида («Слева/Справа» = левый/правый
  профиль ПЕРСОНАЖА; персонаж смотрит в +Z, его левая сторона = +X мира). Статус вида
  показывается всегда; после ручного вращения (событие `start` OrbitControls — только
  от пользовательского ввода) — честный статус «Свободный вид».
- **Touch (Android)** — 1 палец = вращение, pinch = zoom (`controls.touches`), pan
  выключен; 360° вокруг вертикали свободно, полярный угол ограничен
  (0.30 … π−1.05 рад) — модель нельзя случайно перевернуть вверх ногами.
- **Анимация состояний** (idle/listening/… из PoC) сохранена, но по умолчанию
  **выключена** чекбоксом, чтобы микродвижения головы не мешали оценке ракурсов.
