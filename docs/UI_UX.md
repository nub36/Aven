# UI_UX — Интерфейс и пользовательский опыт

> **Статус:** проектная документация. Визуальный дизайн не утверждён; макеты не создавались. Текущее направление — Web-first ([ADR-013](DECISIONS.md)): сайт — самостоятельный полезный продукт, полноценный при работе мышью, клавиатурой, формами и навигацией.
> **Последнее обновление:** 2026-09-25

---

## 1. Главный UX-принцип

**Aven не должен выглядеть как сложная корпоративная CRM.**

Главное: пользователь должен иметь возможность **открыть Aven и сразу написать/сказать**, что ему нужно. Продвинутые настройки и Canvas существуют, но **не мешают** обычному использованию.

## 1.1. Обязательное правило: сайт полезен без голоса (Web-first)

Первая полноценная реализация Aven — **самостоятельный полезный веб-сайт** ([ADR-013](DECISIONS.md)). Пользователь полноценно пользуется основными функциями **мышью, клавиатурой, обычными формами, навигацией**.

**Ни одна базовая функция Aven не должна становиться недоступной только потому, что:**

- нет микрофона;
- пользователь запретил доступ к микрофону;
- STT не поддерживается браузером;
- пользователь не хочет разговаривать;
- TTS отключён.

Для базовых функций должен существовать **обычный UI**. Голос и текстовые команды — **дополнительные** способы управления уже существующими функциями; они не являются условием доступа к функциональности.

## 1.2. Разделы сайта

Предварительная структура Web Aven (проектируется, можно менять; полный состав — [FEATURES.md](FEATURES.md), раздел 2): Главная · День · Календарь · Задачи · Заметки · Финансы · Авто · Покупки/Имущество · Инструменты · Aven Assistant · Автоматизации · Настройки. Календарём, задачами, заметками, финансами и другими разделами можно пользоваться **без ассистента** — через обычные страницы и формы.

**Aven Assistant** — отдельный режим/страница с более свободным интерфейсом (история текущего общения, большое поле команды, микрофон, текстовые/голосовые ответы, Suggestions, результаты действий, уточнения, подтверждения). **Assistant не заменяет обычные страницы сайта.**

**Инструменты** — раздел утилит, полезных сразу; при возможности обработка приватных файлов — локально в браузере.

## 2. Главная страница

Главная — **персональный центр пользователя**. Не должна превращаться в перегруженную панель.

Центральные элементы:

- обращение/приветствие;
- дата;
- ближайшее событие;
- краткий сегодняшний план;
- задачи;
- быстрые действия;
- последние действия;
- расходы / другие пользовательские показатели;
- настраиваемые карточки (пользователь в будущем сможет выбирать отображаемые карточки и их порядок — см. настройки «Главная» в [PROJECT_PLAN.md](PROJECT_PLAN.md));
- строка «Что сделать?»;
- кнопка микрофона — **когда voice доступен**;
- текст ответа Aven;
- возможность голосового ответа;
- завтрашний план;
- Suggestions;
- возможность перехода в соответствующие разделы.

### Пример-макет (концепт из спецификации)

```
Aven
"Добрый вечер, Алексей"

Следующее:
"Стоматолог через 1 час 24 минуты"

[Микрофон] [Что сделать?................]

Пользователь:
"Сколько я сегодня потратил?"

Aven:
"Сегодня записано расходов на 3 420 ₽."
```

Ответ отображается текстом и, если включено, озвучивается.

**Микрофон НЕ обязателен** — текстовый ввод всегда доступен ([ADR-003](DECISIONS.md)).

Для голосового ввода: показывать распознанный текст (прозрачность того, что понял Aven) — деталь прорабатывается при проектировании.

## 3. Утро и вечер (и раздел «День»)

Утренний обзор и вечернее планирование входят в раздел **«День»** — вчера/сегодня/завтра, timeline, события, задачи, напоминания, выполненные действия, быстрое создание записи ([FEATURES.md](FEATURES.md), раздел 2.2).

Предусмотреть концепцию **утреннего и вечернего режима**.

### Утро

- события дня;
- задачи;
- важные сроки;
- напоминания;
- при доступности — погода;
- краткий обзор дня.

### Вечер

- итоги дня;
- невыполненные дела;
- расходы;
- планирование следующего дня.

### Пример вечернего ввода

> **Пользователь:** «Завтра в 10 стоматолог, в 14 забрать посылку, вечером купить продукты.»

Система должна попытаться получить **отдельные события** и дать пользователю возможность **проверить их перед сохранением** (не сохранять молча).

### Пользовательские настройки

Понятия вроде **«утро», «вечер», «после работы»** должны иметь **пользовательские настройки** (границы времени — в профиле, [DATA_MODEL.md](DATA_MODEL.md)). Значения по умолчанию — открытый вопрос ([PROJECT_PLAN.md](PROJECT_PLAN.md)).

## 4. Suggestions (контекстные подсказки)

После выполнения действий Aven может показывать **контекстные следующие действия**.

Пример:

> **Aven:** «Заправка добавлена: 42 литра, 2940 ₽.»
>
> Suggestions:
> - расход топлива;
> - расходы автомобиля;
> - история заправок.

Команда **«Что ты умеешь?»** должна давать **контекстную справку**, а не огромную стену всех возможностей.

## 5. История действий

Пользователь должен иметь историю того, что Aven сделал. Например:

```
19:42 — добавлен расход
19:43 — создано напоминание
19:50 — обновлён пробег
```

Для подходящих действий предусмотрен **Undo** ([ADR-005](DECISIONS.md), [COMMAND_ENGINE.md](COMMAND_ENGINE.md)).

## 6. Честность в интерфейсе

Aven не должен делать вид, что действие выполнено, если оно не выполнено ([ADR-010](DECISIONS.md)). UI отражает реальные статусы:

- успешно;
- ожидает синхронизации;
- запланировано;
- требует подтверждения;
- ошибка;
- недоступно офлайн;
- платформа не поддерживает.

Особенно важно для voice, notifications, integrations и desktop/mobile операций. Индикатор состояния Offline/Sync pending — в интерфейсе ([OFFLINE_SYNC.md](OFFLINE_SYNC.md)).

## 7. Подтверждения опасных действий

Опасные действия подтверждаются явно, с показом последствий:

> «Удали все расходы» → «Будет удалено 1428 записей. Подтвердить?»

Массовое создание (вечерний ввод) — экран проверки перед сохранением (раздел 3).

## 8. Голосовые настройки в UI

Включение/выключение голосовых ответов, выбор голоса, скорость, высота, громкость, язык, тихие часы, правила произнесения, повтор последнего ответа — [VOICE.md](VOICE.md).

## 9. «Память Aven» в UI

Интерфейс просмотра/редактирования/удаления постоянной памяти — [DATA_MODEL.md](DATA_MODEL.md). Пользовательские команды и словарь: Настройки → Aven → Команды и словарь — [COMMAND_ENGINE.md](COMMAND_ENGINE.md).

## 10. Настройки в интерфейсе (/settings)

- **`/settings`** — настройки конкретного пользователя; **`/admin`** — отдельный интерфейс администратора ([ADMIN.md](ADMIN.md)), не для пользовательских настроек. Администратор не действует от имени пользователя автоматически ([ADR-012](DECISIONS.md), [PROJECT_PLAN.md](PROJECT_PLAN.md), раздел 13).
- Категории настроек и их состав — [PROJECT_PLAN.md](PROJECT_PLAN.md), раздел «Настройки Aven»: Профиль; Голос; Поведение Aven; Голосовые события/уведомления; Команды; Персональный словарь; Память; Автоматизации; Модули; Главная; Приватность; Безопасность; Интеграции; Синхронизация; Файлы; Доступность; Экспериментальные функции.
- **Управление настройками командой**: подходящие настройки меняются текстом/голосом через стандартные `settings.*` actions ([PROJECT_PLAN.md](PROJECT_PLAN.md), раздел 12; [ADR-011](DECISIONS.md)).
- **Чувствительные настройки** при изменении командой могут требовать подтверждения и/или повторной аутентификации ([SECURITY.md](SECURITY.md)); перечень — открытый вопрос.
- **UX-принцип действует и для настроек**: продвинутые категории (Canvas, экспериментальные функции, доступность) не должны мешать базовому использованию (раздел 1).
- **Ограничения платформ** в настройках (голос, уведомления, синхронизация) отображаются честно ([ADR-010](DECISIONS.md)).

## 11. Открытые вопросы

1. Визуальный стиль, тёмная/светлая тема, адаптивность — не определены.
2. Дефолтные границы «утро/вечер».
3. Поведение главной страницы на мобильных экранах (приоритет элементов).
4. UX тестирования пользовательских команд (экран «Результат разбора» до выполнения).
5. Представление статусов (иконки/бейджи) и истории действий (глубина, фильтры).
6. Навигация `/settings`: глубина, группировка категорий; какие категории входят в MVP (см. PROJECT_PLAN, открытый вопрос №23).
7. UX управления настройками командой (как показывать изменение, подтверждение чувствительных настроек).
