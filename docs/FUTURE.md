# FUTURE — Будущие платформы и возможности

> **Статус:** проектная документация. Всё в этом документе — **за пределами текущего направления Web-first** (Stage 5–6 и далее; [ADR-013](DECISIONS.md)) и не входит в первый MVP.
> **Последнее обновление:** 2026-09-25

> **Принцип переноса (владелец, 2026-09-25):** сначала создать полезный Aven Web; наблюдать, какие функции действительно используются; после этого определить набор функций Android/iOS. **Web-first ≠ Web-only**: архитектура должна позволять развитие в PWA, Android, iOS, desktop, integrations, но эти платформы — не текущая цель разработки.

---

## 1. Будущие приложения

Aven должен быть спроектирован так, чтобы позже появились:

- **Web**;
- **PWA**;
- **Android**;
- **iOS**;
- **Windows/macOS/Linux agent** (desktop-agent).

Порядок выхода платформ — открытое решение ([PROJECT_PLAN.md](PROJECT_PLAN.md)); логичный ориентир: Web → PWA → Android → iOS → desktop-agent.

### 1.1. Мобильное приложение (будущее, Stage 5–6)

**На текущем этапе не реализовывать:** Android; iOS; mobile offline database; background mobile voice; постоянное прослушивание; сложную device synchronization. При этом не создавать искусственных архитектурных препятствий будущим клиентам: Backend/API и Business Logic должны проектироваться так, чтобы позже их могли использовать другие доверенные клиенты.

Должно позволять:

- работать с локальной БД;
- использовать голос (системные TTS/STT и/или локальные движки — [VOICE.md](VOICE.md));
- системные уведомления;
- часть возможностей офлайн ([OFFLINE_SYNC.md](OFFLINE_SYNC.md));
- синхронизироваться с сервером.

Кандидат стека: Flutter/Dart, локальная БД SQLite ([DECISIONS.md](DECISIONS.md), ADR-104 — `Proposed`).

### 1.2. Desktop Agent (будущее)

**На текущем этапе не реализовывать:** запуск программ; управление ОС; файловую систему пользователя; shutdown; desktop monitoring.

- Запускается **только с явного согласия** пользователя.
- Имеет **контролируемые permissions**.
- Может предоставлять **разрешённые системные действия**.

Примеры будущих команд:

- «Открой Steam.»
- «Покажи свободное место.»
- «Открой папку проекта.»
- «Передай файл на компьютер.»

Кандидат стека: Rust + Tauri ([DECISIONS.md](DECISIONS.md), ADR-105 — `Proposed`).

**Не считать эти функции частью первого MVP.**

## 2. AI-слой (опциональный)

Подробно — [ARCHITECTURE.md](ARCHITECTURE.md), раздел 6. Схема:

```
Human input → AI Router (опционально) → строго определённый Action + parameters → permission validation → execution
```

Возможные применения: свободный language parser; intent router; помощник по сложным запросам; дополнительный интерфейс. Без AI и интернета основные функции продолжают работать ([ADR-002](DECISIONS.md)).

## 7. Честные ограничения

- Закрытый браузер не может сам произнести голосовое сообщение; Web Push и возможности браузера/ОС имеют ограничения ([VOICE.md](VOICE.md)). Мобильные приложения в будущем расширяют фоновые возможности.
- Все возможности этого документа декларируются в интерфейсе только тогда, когда платформа реально их поддерживает.
