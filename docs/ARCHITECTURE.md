# ARCHITECTURE — Архитектура Aven

> **Статус:** проектная документация (design). Архитектура в стадии проектирования; реализация не начата; стек — см. [DECISIONS.md](DECISIONS.md) (кандидаты имеют статус `Proposed`/`Under Discussion`) и [PROJECT_PLAN.md](PROJECT_PLAN.md), раздел «Статус архитектуры». ADR не является запретом на изменение архитектуры.
> **Текущее направление:** Web-first ([ADR-013](DECISIONS.md), Product Direction) — первая полноценная реализация: самостоятельный полезный веб-сайт.
> **Последнее обновление:** 2026-09-25

## 1. Что такое Aven с точки зрения системы

Aven — персональный цифровой помощник и центр управления личными данными, делами, инструментами и автоматизациями. Не чат-бот: основная ценность — превращение естественных фраз (голос/текст) в **надёжные действия** над персональными данными при полном контроле пользователя.

Три опоры архитектуры:

1. **Command Engine** — детерминированное понимание команд без генеративного AI ([COMMAND_ENGINE.md](COMMAND_ENGINE.md)).
2. **Action Core** — единый контракт действий для всех источников команд (этот документ, раздел 4).
3. **Модульные данные и автоматизации** — расширяемые сущности и связи ([DATA_MODEL.md](DATA_MODEL.md)), визуальные автоматизации ([AUTOMATION.md](AUTOMATION.md)).

## 2. Основные принципы

- **Web-first** ([ADR-013](DECISIONS.md)): первая полноценная реализация — самостоятельный полезный веб-сайт. Основные функции полноценно доступны мышью, клавиатурой, обычными формами, навигацией. Не оболочка мобильного приложения, не только голосовой ассистент, не только чат, не пустой dashboard, не демонстрация технологий.
- **Голос и текстовые команды — дополнительные способы управления уже существующими функциями.** Пользователь взаимодействует голосом **и** текстом; текстовый ввод всегда доступен; микрофон не обязателен.
- Ответ может одновременно показываться текстом и озвучиваться.
- Основные возможности не зависят от платного AI; AI — дополнительный слой, а не ядро.
- Частичная работа без интернета — желаемое будущее свойство; сложная offline-синхронизация не является условием запуска web-версии ([OFFLINE_SYNC.md](OFFLINE_SYNC.md), [ADR-007](DECISIONS.md)).
- Расширение модулями; пользовательские типы сущностей ([DATA_MODEL.md](DATA_MODEL.md)).
- Пользователь контролирует память, данные, команды и автоматизации ([DATA_MODEL.md](DATA_MODEL.md), [SECURITY.md](SECURITY.md)).
- Опасные действия требуют подтверждения ([COMMAND_ENGINE.md](COMMAND_ENGINE.md), раздел 6).
- Приватность и безопасность с самого начала ([SECURITY.md](SECURITY.md)).
- В будущем (Stage 5–6): мобильные приложения и desktop-agent ([FUTURE.md](FUTURE.md)).

## 3. Общая схема (верхний уровень)

```
Источники команд                         Ядро                            Данные и исполнение
┌──────────────────────┐    ┌───────────────────────────────┐    ┌─────────────────────────────┐
│ Web UI (текст/голос) │    │ Command Engine                │    │ Модули (день, задачи, авто, │
│ Mobile (будущее)     │ →  │ нормализация → intent →       │ →  │ финансы, память, ...)       │
│ Automation           │    │ параметры → entities →        │    │ Action Core → выполнение    │
│ API                  │    │ confidence → уточнения →      │    │ Хранилища (БД, файлы, кэш)  │
│ Desktop-agent (буд.) │    │ подтверждение → Action        │    │ Уведомления                 │
│ AI Router (будущее,  │    └───────────────────────────────┘    │ Синхронизация (офлайн)      │
│ опционально)         │                                         └─────────────────────────────┘
└──────────────────────┘
```

### 3.1. Единый путь действия (Web-first, [ADR-013](DECISIONS.md))

```
UI / Forms
        \
Text command → Action Core → Business Logic → Data
        /
Voice → STT → Text command

Result → UI
       → Text response
       → TTS (если включено)
```

Отдельная бизнес-логика для UI, текста и голоса **не создаётся**: все пути ведут к одному Action/Use Case (пример — [FEATURES.md](FEATURES.md), раздел 2.7).

Подробная декомпозиция Command Engine — [COMMAND_ENGINE.md](COMMAND_ENGINE.md); голосовой путь — [VOICE.md](VOICE.md).

## 4. Action Core

Независимо от источника команда превращается в **стандартное действие**.

Источники:

- UI (формы/навигация — первоклассный источник при Web-first);
- текст (командная строка «Что сделать?», Assistant; Stage 2);
- голос (Stage 3, поверх Command Engine);
- Automation;
- API;
- в будущем — AI.

Примеры стандартных действий:

```
ADD_EXPENSE
ADD_FUEL
CREATE_REMINDER
CREATE_NOTE
GET_DAY_PLAN
SEARCH_DATA
UPDATE_MILEAGE
RUN_AUTOMATION
SPEAK
```

Правила:

- Бизнес-логика **не дублируется** отдельно для голоса и обычного UI.
- Каждое действие имеет: параметры (с типами), требуемые permissions, класс опасности (требует ли подтверждения), результат со статусом.
- Внутренние идентификаторы intents/actions — на английском (`expense.add`, `ADD_EXPENSE`); формулировки для пользователя — на языке пользователя через шаблоны ответов.
- Через Action Core идут и **команды изменения настроек** (`settings.voice.rate.set`, `settings.quiet_hours.set`, `settings.day_period.set`, `dictionary.alias.create`, `settings.voice.enabled.set`, `settings.confirmation_policy.set` — [ADR-011](DECISIONS.md), [PROJECT_PLAN.md](PROJECT_PLAN.md), раздел 12); они не обходят security requirements — для чувствительных настроек требуются подтверждение и/или повторная аутентификация.

Пример преобразования фразы:

```
«Потратил сегодня 1250 рублей на бензин»
→ intent = expense.add
  amount = 1250
  currency = RUB
  category = fuel
  date = today
```

## 5. Command Engine (сводка)

Подробно — [COMMAND_ENGINE.md](COMMAND_ENGINE.md). Состав компонентов: нормализация текста; определение намерения; извлечение параметров; разбор дат, времени, денежных значений, чисел; Entity Resolver; контекст; confidence score; запрос недостающих параметров; подтверждение; выполнение Action; генерация шаблонного ответа.

Если информации недостаточно — Aven задаёт уточнение («Напомни завтра позвонить» → «В какое время?» → «В десять» → создание напоминания завершено). Потенциально опасные или существенные данные не угадываются.

## 6. AI — OPTIONAL, NOT REQUIRED

Первая архитектура **не требует** платного LLM API для базовой работы.

В будущем AI может использоваться как:

- более свободный language parser;
- intent router;
- помощник по сложным запросам;
- дополнительный интерфейс.

Предпочтительная схема:

```
Human input
→ AI Router (опционально)
→ строго определённый Action + parameters
→ permission validation
→ execution
```

Ограничения:

- AI **не имеет неконтролируемого прямого доступа** к базе или системным операциям.
- При отсутствии AI или интернета основные функции продолжают работать.

## 7. Голосовой слой

Голос — **слой поверх текстового Command Engine** (Stage 3): Business Logic не связывается непосредственно с Speech Recognition (`audio → STT → text → Command Engine`). Заменяемый слой STT/TTS, изолированный за интерфейсами. Для веб-версии рассматриваются системные браузерные возможности (Speech Synthesis API — TTS; Web Speech API — STT там, где доступно); поддержка браузерами **не считается гарантированной**, предусмотрен fallback на текст; ни одна базовая функция не зависит от микрофона/STT/TTS ([PROJECT_PLAN.md](PROJECT_PLAN.md), раздел 6.2). Полная спецификация — [VOICE.md](VOICE.md).

## 8. Память и данные

Память Aven — контролируемая, разделена на профиль, объекты, факты, структурированную историю, временный контекст диалога, пользовательский словарь и команды, сценарии/автоматизации, предпочтения поведения. Есть интерфейс «Память Aven» для просмотра/редактирования/удаления. Aven не сохраняет бесконтрольно каждую фразу как постоянную память. Сущности связываются между собой без дублирования данных. Подробно — [DATA_MODEL.md](DATA_MODEL.md).

## 9. Автоматизации

Automation Canvas — node-based редактор (класс n8n, собственная реализация и UX), **Stage 4**: реализуется после стабилизации базовых данных и Action Core и не должен задерживать создание полезного сайта. На раннем этапе возможны готовые автоматизации, простые правила, расписания. Workflow сохраняются и выполняются независимо от открытого редактора, если их характер это предполагает. Запрет произвольного пользовательского JS на сервере; каждый серверный блок — зарегистрированная операция (входы, выходы, permissions, validation, resource limits). Подробно — [AUTOMATION.md](AUTOMATION.md).

## 10. Offline (перспектива)

Offline/local-first — желаемое будущее свойство (особенно для мобильных приложений); **не** обязательное условие запуска первой web-версии. Для Web допустимы локальные возможности браузера там, где это даёт практическую пользу, без сложной распределённой sync-системы до подтверждённой необходимости. Части [OFFLINE_SYNC.md](OFFLINE_SYNC.md) — статус Future/Under Design.

## 11. Честность статусов

Aven не должен делать вид, что действие выполнено, если оно не выполнено. Различаются:

- успешно;
- ожидает синхронизации;
- запланировано;
- требует подтверждения;
- ошибка;
- недоступно офлайн;
- платформа не поддерживает.

Это особенно важно для voice, notifications, integrations и desktop/mobile операций.

## 12. Безопасность и приватность

Security by design: хеширование паролей современным алгоритмом, безопасные сессии/tokens, CSRF/XSS/SQLi-защиты, валидация, authorization на каждом объекте, rate limiting, шифрование secrets, разделение данных пользователей, аудит админ-действий, управление устройствами/сессиями, 2FA, backup + restore testing, export/delete account, least privilege, явные permissions для device-агентов и интеграций, подтверждение разрушительных действий. Подробно — [SECURITY.md](SECURITY.md) и [ADMIN.md](ADMIN.md).

## 13. Кроссплатформенность (перспектива, Stage 5–6)

**Web-first ≠ Web-only** ([ADR-013](DECISIONS.md)): архитектура должна позволять дальнейшее развитие в PWA, Android, iOS, desktop, integrations — но эти платформы не являются текущей целью разработки. Не создавать искусственных архитектурных препятствий будущим клиентам: **Backend/API и Business Logic проектируются так, чтобы позже их могли использовать другие доверенные клиенты**. Сначала — полезный и проверенный веб-продукт; затем по реальному использованию определяется набор функций мобильных приложений. Desktop-agent — только с явного согласия, контролируемые permissions. Подробно — [FUTURE.md](FUTURE.md).
