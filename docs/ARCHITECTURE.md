## 1. Что такое Aven с точки зрения системы

Aven — персональный цифровой помощник и центр управления личными данными, делами, инструментами и автоматизациями. Не чат-бот: основная ценность — превращение естественных фраз (голос/текст) в **надёжные действия** над персональными данными при полном контроле пользователя.

Три опоры архитектуры:

1. **Command Engine** — детерминированное понимание команд без генеративного AI ([COMMAND_ENGINE.md](COMMAND_ENGINE.md)).
2. **Action Core** — единый контракт действий для всех источников команд (этот документ, раздел 4).
3. **Модульные данные и автоматизации** — расширяемые сущности и связи ([DATA_MODEL.md](DATA_MODEL.md)), визуальные автоматизации ([AUTOMATION.md](AUTOMATION.md)).

## 2. Основные принципы

- Пользователь взаимодействует голосом **и** текстом; текстовый ввод всегда доступен; микрофон не обязателен.
- Ответ может одновременно показываться текстом и озвучиваться.
- Основные возможности не зависят от платного AI; AI — дополнительный слой, а не ядро.
- Возможность частично работать без интернета ([OFFLINE_SYNC.md](OFFLINE_SYNC.md)).
- Расширение модулями; пользовательские типы сущностей ([DATA_MODEL.md](DATA_MODEL.md)).
- Пользователь контролирует память, данные, команды и автоматизации ([DATA_MODEL.md](DATA_MODEL.md), [SECURITY.md](SECURITY.md)).
- Опасные действия требуют подтверждения ([COMMAND_ENGINE.md](COMMAND_ENGINE.md), раздел 6).
- Приватность и безопасность с самого начала ([SECURITY.md](SECURITY.md)).
- В будущем: мобильные приложения и desktop-agent ([FUTURE.md](FUTURE.md)).

## 3. Общая схема (верхний уровень)

```
Источники команд                         Ядро                            Данные и исполнение
┌──────────────────────┐    ┌───────────────────────────────┐    ┌─────────────────────────────┐
│ Web UI (текст/голос) │    │ Command Engine                │    │ Модули (день, задачи, авто, │
│ Mobile (будущее)     │ →  │ нормализация → intent →       │ →  │ финансы, память, ...)       │
│ Automation           │    │ параметры → entities →        │    │ Action Core → выполнение    │
│ API                  │    │ confidence → уточнения →      │    │ Хранилища (БД, файлы, кэш)  │
│ Desktop-agent (буд.) │    │ подтверждение → Action        │    │ Уведомления                 │
│ AI Router (будущее,  │    └───────────────────────────────┘    │ Синхронизация (офлайн)      │
│ опционально)         │                                         └─────────────────────────────┘
└──────────────────────┘
```

Подробная декомпозиция Command Engine — [COMMAND_ENGINE.md](COMMAND_ENGINE.md); голосовой путь — [VOICE.md](VOICE.md).

## 4. Action Core

Независимо от источника команда превращается в **стандартное действие**.

Источники:

- UI;
- текст;
- голос;
- Automation;
- API;
- в будущем — AI.

Примеры стандартных действий:

```
ADD_EXPENSE
ADD_FUEL
CREATE_REMINDER
CREATE_NOTE
GET_DAY_PLAN
SEARCH_DATA
UPDATE_MILEAGE
RUN_AUTOMATION
SPEAK
```

Правила:

- Бизнес-логика **не дублируется** отдельно для голоса и обычного UI.
- Каждое действие имеет: параметры (с типами), требуемые permissions, класс опасности (требует ли подтверждения), результат со статусом.
- Внутренние идентификаторы intents/actions — на английском (`expense.add`, `ADD_EXPENSE`); формулировки для пользователя — на языке пользователя через шаблоны ответов.

Пример преобразования фразы:

```
«Потратил сегодня 1250 рублей на бензин»
→ intent = expense.add
  amount = 1250
  currency = RUB
  category = fuel
  date = today
```

## 5. Command Engine (сводка)

Подробно — [COMMAND_ENGINE.md](COMMAND_ENGINE.md). Состав компонентов: нормализация текста; определение намерения; извлечение параметров; разбор дат, времени, денежных значений, чисел; Entity Resolver; контекст; confidence score; запрос недостающих параметров; подтверждение; выполнение Action; генерация шаблонного ответа.

Если информации недостаточно — Aven задаёт уточнение («Напомни завтра позвонить» → «В какое время?» → «В десять» → создание напоминания завершено). Потенциально опасные или существенные данные не угадываются.

## 6. AI — OPTIONAL, NOT REQUIRED

Первая архитектура **не требует** платного LLM API для базовой работы.

В будущем AI может использоваться как:

- более свободный language parser;
- intent router;
- помощник по сложным запросам;
- дополнительный интерфейс.

Предпочтительная схема:

```
Human input
→ AI Router (опционально)
→ строго определённый Action + parameters
→ permission validation
→ execution
```

Ограничения:

- AI **не имеет неконтролируемого прямого доступа** к базе или системным операциям.
- При отсутствии AI или интернета основные функции продолжают работать.

## 7. Голосовой слой

Заменяемый слой STT/TTS, изолированный за интерфейсами. Для веб-MVP рассматриваются системные браузерные возможности (Speech Synthesis API — TTS; Web Speech API — STT там, где доступно); поддержка браузерами **не считается гарантированной**, предусмотрен fallback на текст. Полная спецификация — [VOICE.md](VOICE.md).

## 8. Память и данные

Память Aven — контролируемая, разделена на профиль, объекты, факты, структурированную историю, временный контекст диалога, пользовательский словарь и команды, сценарии/автоматизации, предпочтения поведения. Есть интерфейс «Память Aven» для просмотра/редактирования/удаления. Aven не сохраняет бесконтрольно каждую фразу как постоянную память. Сущности связываются между собой без дублирования данных. Подробно — [DATA_MODEL.md](DATA_MODEL.md).

## 9. Автоматизации

Automation Canvas — node-based редактор (класс n8n, собственная реализация и UX). Workflow сохраняются и выполняются независимо от открытого редактора, если их характер это предполагает. Запрет произвольного пользовательского JS на сервере; каждый серверный блок — зарегистрированная операция (входы, выходы, permissions, validation, resource limits). Подробно — [AUTOMATION.md](AUTOMATION.md).

## 10. Offline-first

Часть функций доступна без интернета; при восстановлении — безопасная синхронизация, разрешение конфликтов, статус pending sync. Состояния: Online / Offline / Sync pending / Local-private data (будущее). Подробно — [OFFLINE_SYNC.md](OFFLINE_SYNC.md).

## 11. Честность статусов

Aven не должен делать вид, что действие выполнено, если оно не выполнено. Различаются:

- успешно;
- ожидает синхронизации;
- запланировано;
- требует подтверждения;
- ошибка;
- недоступно офлайн;
- платформа не поддерживает.

Это особенно важно для voice, notifications, integrations и desktop/mobile операций.

## 12. Безопасность и приватность

Security by design: хеширование паролей современным алгоритмом, безопасные сессии/tokens, CSRF/XSS/SQLi-защиты, валидация, authorization на каждом объекте, rate limiting, шифрование secrets, разделение данных пользователей, аудит админ-действий, управление устройствами/сессиями, 2FA, backup + restore testing, export/delete account, least privilege, явные permissions для device-агентов и интеграций, подтверждение разрушительных действий. Подробно — [SECURITY.md](SECURITY.md) и [ADMIN.md](ADMIN.md).

## 13. Кроссплатформенность (перспектива)

Архитектура проектируется так, чтобы позже появились: Web, PWA, Android, iOS, Windows/macOS/Linux agent. Мобильные приложения — локальная БД, системный голос и уведомления, офлайн, синхронизация с сервером. Desktop-agent — только с явного согласия, контролируемые permissions, разрешённые системные действия. Подробно — [FUTURE.md](FUTURE.md). Эти функции **не входят** в первый MVP.
