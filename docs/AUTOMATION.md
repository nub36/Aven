## 1. Automation Canvas

Одна из **ключевых будущих возможностей** Aven — визуальные автоматизации в стиле node-based редактора (по концепции похожего класса на n8n, но **собственная реализация и UX**).

Пользователь получает поле/canvas:

- на нём размещаются блоки;
- блоки соединяются связями;
- workflow сохраняется.

### Примеры workflow

**Утренний обзор:**

```
[Каждый день 08:00]
→ [Получить события сегодня]
→ [Получить задачи]
→ [Сформировать обзор]
→ [Произнести]
```

**Контроль расхода топлива:**

```
[Добавлена заправка]
→ [Посчитать статистику]
→ [Если расход > значение]
→ [Показать предупреждение]
```

### Типы блоков

- Trigger;
- Schedule;
- Action;
- Condition/IF;
- Delay;
- Variables;
- Math;
- Data;
- HTTP/API;
- Webhook;
- Loop;
- Output;
- Speak;
- Notification;
- User data;
- Device — в будущем.

### Исполнение

Workflow сохраняется и **выполняется независимо от открытого редактора**, если характер workflow это предполагает.

## 2. Безопасность исполнения (критично)

**НЕЛЬЗЯ по умолчанию выполнять произвольный пользовательский JavaScript на production-сервере** ([ADR-006](DECISIONS.md)).

Каждый серверный блок — **заранее зарегистрированная операция** с определёнными:

- входами;
- выходами;
- permissions;
- validation;
- resource limits.

Это относится к исполнению workflow, аудитe выполнений и лимитам ресурсов (см. [ADMIN.md](ADMIN.md), раздел Automation).

---

## 3. Готовые автоматизации (templates)

Обычный пользователь **не должен быть обязан** разбираться в Canvas. Предусмотреть шаблоны:

- Утренний обзор;
- Вечернее планирование;
- Контроль расходов;
- Автомобиль;
- Страховка;
- Регулярные платежи;
- собственные шаблоны в будущем.

Связь с режимами утро/вечер — [UI_UX.md](UI_UX.md).

---

## 4. Автоматизации и Action Core

Блоки типа Action/Speak/Notification/User data не содержат собственной бизнес-логики — они вызывают те же зарегистрированные действия Action Core, что и UI/голос/API ([ARCHITECTURE.md](ARCHITECTURE.md), раздел 4). Пользовательская команда может быть связана с Automation Workflow ([COMMAND_ENGINE.md](COMMAND_ENGINE.md), раздел 4).

## 5. Офлайн

Выполнение автоматизаций, требующих сервера, недоступно офлайн — соответствующий статус честно отображается ([ADR-010](DECISIONS.md), [OFFLINE_SYNC.md](OFFLINE_SYNC.md)).

## 6. Открытые вопросы

1. Canvas — поздняя часть MVP или следующий этап: **решить отдельно**.
2. Движок исполнения workflow (связь с выбором очереди/воркеров — [DECISIONS.md](DECISIONS.md), ADR-106).
3. Триггеры внешних событий (webhook, HTTP/API, внешние интернет-события) — детальная спецификация и лимиты.
4. Версионирование workflow и поведение при изменении зарегистрированных блоков.
5. Отладка/логирование запусков для пользователя (история выполнений в UI).
