# COMMAND_ENGINE — Движок команд Aven

> **Статус:** проектная документация. Пороги confidence — НЕ утверждены (см. раздел 6 и открытые вопросы в [PROJECT_PLAN.md](PROJECT_PLAN.md)).
> **Первая итерация реализована в UX-прототипе 2026-09-28** — фактический контракт и охват см. раздел 9 (это прототип, не production-реализация).
> **Последнее обновление:** 2026-09-28

## 1. Назначение

Command Engine — ядро понимания команд. **Основные функции Aven должны работать без генеративного AI** ([ADR-002](DECISIONS.md)). Внутри используются intents/actions ([ADR-004](DECISIONS.md)).

Вся внутренняя система работает с **текстовым представлением команды** — голос лишь превращается в текст до входа в движок ([ADR-003](DECISIONS.md)).

**Место в порядке развития — Stage 2** ([ADR-013](DECISIONS.md)): Command Engine подключается к **уже существующим функциям сайта** (Stage 1 — полезный самостоятельный веб-сайт) и даёт возможность выполнять их одной строкой. Команды — дополнительный путь к тем же Actions: **те же действия остаются доступными через обычный UI** (формы, кнопки, навигация). Отдельная бизнес-логика для UI, текста и голоса не создаётся.

### Примеры intents

```
expense.add
expense.stats
car.fuel.add
car.mileage.set
note.create
note.search
event.create
event.list
timer.start
task.create
automation.run
memory.add
memory.search
```

### Примеры settings-intents (управление настройками командой)

Пользователь может менять подходящие настройки текстом/голосом ([PROJECT_PLAN.md](PROJECT_PLAN.md), раздел 12; [ADR-011](DECISIONS.md)). Примеры действий:

```
settings.voice.rate.set          ← «Говори медленнее.»
settings.quiet_hours.set         ← «Не разговаривай после 23:00.»
settings.day_period.set          ← «Вечер для меня начинается в 18:30.»
dictionary.alias.create          ← «Называй BMW бэхой.»
settings.voice.enabled.set       ← «Отключи голосовые ответы.»
settings.confirmation_policy.set ← «Всегда спрашивай перед удалением.»
```

Полный набор `settings.*` actions и охват «подходящих» настроек — открытый вопрос.

### Примеры команд (Stage 2)

- «Добавь задачу купить фильтр.»
- «Запиши 850 рублей продукты.»
- «Покажи расходы за неделю.»
- «Добавь заправку 42 литра на 3000.»
- «Создай заметку...»
- «Что у меня завтра?»

Те же действия доступны через обычный UI соответствующих разделов.

**Прототипная подготовка (2026-09-27, не полноценный NLP):** `/prototype/js/actions.js` уже даёт DOM-free действия для задач/событий (`createTask`, `completeTask`, `createEvent`, `getEventsForDate`, `getOverdueTasks` и др.). Текущий Assistant использует только простые demo-routes/state-machine, но путь для Stage 2 проверен: `text → intent (будет позже) → parameters → Common Action → state/history → UI/response`. Голос в Stage 3 должен идти тем же путём через STT-текст, а не через отдельные `voiceCreateTask()`/`voiceCreateEvent()`.

### Пример преобразования

Фраза: **«Потратил сегодня 1250 рублей на бензин»**

```
intent    = expense.add
amount    = 1250
currency  = RUB
category  = fuel
date      = today
```

## 2. Конвейер обработки

Command Engine состоит из отдельных компонентов:

1. нормализация текста;
2. определение намерения (intent detection);
3. извлечение параметров;
4. разбор дат;
5. разбор времени;
6. разбор денежных значений;
7. разбор чисел;
8. Entity Resolver (связывание упоминаний с объектами пользователя);
9. контекст (диалоговый);
10. confidence score;
11. запрос недостающих параметров (уточнения);
12. подтверждение (для опасных/существенных);
13. выполнение Action (через Action Core, [ARCHITECTURE.md](ARCHITECTURE.md));
14. генерация шаблонного ответа.

Если информации недостаточно, Aven задаёт уточнение.

Пример:

> **Пользователь:** «Напомни завтра позвонить.»
> **Aven:** «В какое время?»
> **Пользователь:** «В десять.»
> **Aven:** завершает создание напоминания.

Не угадывать потенциально опасные или существенные данные. Для опасных операций всегда использовать подтверждение.

## 3. Естественная речь без AI

Используются:

- синонимы;
- морфологическая нормализация;
- шаблоны;
- fuzzy matching с ограничениями;
- entity resolution;
- контекст;
- state machine для уточнений;
- персональный словарь;
- пользовательские команды.

Примеры системных синонимов:

| Фразы | Нормализуется к |
|---|---|
| потратил / заплатил / оплатил | расход |
| напомни / предупреди / скажи | reminder |
| машина / автомобиль / авто | vehicle |
| запиши / сохрани / добавь | create |

Система **не должна требовать точного синтаксиса команд**.

## 4. Пользовательские команды

Концепция: **Настройки → Aven → Команды и словарь**.

Пользователь может:

- добавлять команду;
- отключать команду;
- редактировать команду;
- задавать альтернативные фразы;
- связывать команду с Action;
- связывать команду с Automation Workflow;
- тестировать распознавание.

Поддерживаемые шаблоны (примеры):

- «залил {литры} литров»
- «заправился на {сумма}»
- «запиши {сумма} на {категория}»
- «напомни {дата} в {время} {текст}»

Типы параметров (расширяемые):

- number;
- money;
- text;
- date;
- time;
- datetime;
- vehicle;
- person;
- place;
- category;
- пользовательские типы в будущем.

## 5. Персональный словарь

Пользователь задаёт собственные значения слов и выражений:

| Выражение | Значение |
|---|---|
| «бэха» | BMW 530d |
| «моя машина» | основной автомобиль |
| «хата» | Дом |
| «работа» | сохранённый адрес «Работа» |
| «маман» | контакт «Мама» |
| «основная карта» | выбранный финансовый счёт |

Правила:

- Персональный словарь имеет **приоритет над общесистемным** там, где это безопасно и однозначно.
- Поддерживаются слова и словосочетания.
- Существует **проверка конфликтов** команд/синонимов.

### Режим тестирования

Ввод: **«я вчера залил в бэху 45 литров на 3200»**

Результат разбора:

```
Команда:    Добавить заправку
Автомобиль: BMW
Дата:       вчера
Литры:      45
Сумма:      3200 ₽
```

**До фактического выполнения в режиме теста ничего не изменять.**

## 6. Confidence и безопасность команд

Предусмотрена оценка уверенности распознавания. **Конкретные пороги пока НЕ считать окончательно утверждёнными.**

Принцип:

| Уверенность | Тип действия | Поведение |
|---|---|---|
| высокая | безопасное | можно выполнить |
| средняя | любое | уточнить / подтвердить |
| низкая | любое | попросить переформулировать |
| любая | **опасное действие** | подтверждение **независимо** от confidence |

Пример:

> **Пользователь:** «Удали все расходы.»
> **Aven:** «Будет удалено 1428 записей. Подтвердить?»

Дополнительно:

- Существует **история действий**.
- Для подходящих действий предусмотрен **Undo**.
- **Команды изменения настроек не обходят security requirements**: для чувствительных настроек используется подтверждение и/или повторная аутентификация ([ADR-011](DECISIONS.md), [SECURITY.md](SECURITY.md)). Голосовой ввод не даёт никаких привилегий — все команды проходят одинаковые проверки.

---

## 7. Шаблонные ответы

Для базовых функций AI не требуется: ответы строятся из шаблонов и данных.

Примеры:

- «В сентябре вы потратили на {car} {amount}.»
- «Готово. Напомню {time}.»
- «У вас несколько автомобилей. Какой выбрать?»

Правила:

- Можно иметь несколько вариантов формулировок, но ответ **не должен искажать фактические данные**.
- Ответ отражает реальный статус выполнения ([ADR-010](DECISIONS.md)).

## 8. Открытые вопросы

1. Числовые пороги confidence и их привязка к классам опасности действий — не утверждены.
2. Языки движка на старте (русский первым?), масштабирование синонимов/морфологии на другие языки.
3. Механизм разрешения конфликтов между системными и пользовательскими синонимами (детальные правила приоритета).
4. Формат хранения пользовательских шаблонов и типизация параметров — детальная спецификация.
5. Поведение при неоднозначном Entity Resolver (несколько кандидатов) — уточнение vs выбор по умолчанию.
6. Полный набор `settings.*` actions и охват «подходящих» настроек, изменяемых командой (PROJECT_PLAN, вопрос №20).
7. Перечень «чувствительных» настроек, требующих подтверждения/повторной аутентификации (PROJECT_PLAN, вопрос №19).

## 9. Первая итерация в прототипе (2026-09-28, фактическое состояние)

> Это **фактический** отчёт о том, что реализовано в `/prototype`, а не план. Всё, чего нет в
> списке «Поддерживается», считается не поддержанным. Production-реализации по-прежнему нет.

### 9.1. Контракт

Модуль `prototype/js/command.js` (`window.AvenCommand`) — DOM-free ядро:

```
normalize(text)              → нормализованная строка
parse(text, context)         → intent | { ok:false, error:{ code, message, examples } }   (без side effects)
execute(intent, context)     → result (вызывает только существующие Common Actions/Queries)
respond(result)              → человеческий текст
respondToParseError(parsed)  → человеческий текст
run(text, context)           → { ok, intent, result, response, context }
supported() / examples()     → перечень возможностей для UI, справки и тестов
```

Структурированное намерение:

```
{ ok: true, kind: 'query' | 'mutation', domain, action, params,
  match: { rule, confidence }, requiresConfirmation: false,
  input: { text, normalized }, context: { todayISO } }
```

Структурированный результат:

```
{ ok, status: 'done' | 'info' | 'ambiguous' | 'not_found' | 'invalid',
  action, intent, entity?, data?, historyId?, candidates?, code?, message? }
```

Правила слоя: ядро не меняет состояние напрямую, не пишет собственную историю, не дублирует
бизнес-логику задач/событий/финансов, не использует системные часы (только `AvenActions.dates`),
не использует AI/LLM/сеть/STT. Экран помощника — тонкий адаптер над `run()`.

### 9.2. Поддерживается сейчас

| Команда (примеры) | Действие | Через что выполняется |
|---|---|---|
| «Что у меня сегодня?», «что сегодня», «покажи дела на сегодня», «Что у меня завтра?», «какой план на послезавтра» | `day.plan` | `tasks.getTasksForDate`, `events.getEventsForDate`, `tasks.getOverdueTasks` |
| «Покажи просроченные задачи» | `tasks.overdue` | `tasks.getOverdueTasks` |
| «Какие есть предложения?» | `suggestions.list` | `AvenSuggestions.getSuggestions` |
| «Сколько я потратил?» | `finance.summary` | `finance.summary`, `finance.getOperations` (только чтение) |
| «Какой пробег?» | `auto.status` | `auto.car/stats`, `finance.totals` (только чтение) |
| «Что ты умеешь?» | `help.capabilities` | перечень `supported()` |
| «Создай/добавь/запиши задачу … [на завтра] [в 10:30]» | `task.create` | `tasks.createTask` |
| «Добавь завтра в 10 встречу с Сергеем» | `event.create` | `events.createEvent` |
| «Отметь/заверши/выполни … выполненной» | `task.complete` | `tasks.completeTask` |
| «Перенеси задачу … на пятницу» | `task.reschedule` | `tasks.updateTask` |

Даты: «сегодня», «завтра», «послезавтра», «вчера», дни недели (ближайший будущий),
`дд.мм[.гггг]`, `гггг-мм-дд`. Дата без года трактуется как ближайшая будущая.
Время: «в 10», «в 10 часов», «в 10:30», «10:30». Форма «10.30» намеренно не поддерживается
(неотличима от даты). Несуществующие дата/время — ошибка, а не «почти правильно».

Нормализация: регистр, `ё → е`, повторные и неразрывные пробелы, кавычки, завершающая пунктуация.
Морфологического анализатора, fuzzy-подбора и персонального словаря в первой итерации **нет**.

### 9.3. Явно НЕ поддерживается в первой итерации

- удаление и любые массовые/разрушительные операции текстом (нет подтверждения для текстового
  пути — по разделу 6 и [ADR-005](DECISIONS.md) такие команды в итерацию не включены);
- расходы/доходы, заметки, покупки, заправки и обслуживание, напоминания — текстом;
- перенос и изменение событий (создание есть, изменение — только в «Календаре»);
- уточняющие вопросы в несколько шагов (раздел 2, п. 11) и диалоговый контекст;
- пользовательские команды, персональный словарь, `settings.*`-команды (разделы 4–5);
- числовые confidence-пороги (раздел 6) — намерение помечается `confidence: 'high'` только
  при полном совпадении шаблона, иных уровней пока нет;
- голос/STT (Stage 3) и любой LLM/AI.

### 9.4. Безопасность в первой итерации

- Разбор текста не меняет данные; изменения возможны только после успешного разбора и проверки.
- Несколько подходящих задач → структурированная неоднозначность со списком вариантов, мутации нет.
- Ничего не найдено / ошибка проверки общего слоя → причина словами, мутации нет.
- Неизвестная команда → отказ с примерами; данные и история не меняются.
- История и Undo — только существующие, созданные общим слоем действий.

Проверка: `prototype/tests/command-engine-check.js` — **143 проверки, 0 провалов** (в том числе
негативные: неизвестный текст, неоднозначность, неверные дата/время, отказ общего действия,
отсутствие подтверждения для разрушительных команд).
