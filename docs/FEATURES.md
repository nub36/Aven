- текстовые ответы;
- голосовые ответы;
- Suggestions;
- результаты действий;
- уточнения;
- подтверждения.

## 3. Возможности помощника

### 3.1. Главная Aven **[MVP-черновик]**

Состав — раздел 2.1. Ответ отображается текстом и, если включено, озвучивается. **Микрофон НЕ обязателен** — текстовый ввод всегда доступен ([ADR-003](DECISIONS.md)). Концепт-макет — [UI_UX.md](UI_UX.md).

### 3.2. Текстовые команды **[Stage 2; три итерации есть в прототипе (2026-09-28)]**

Когда Command Engine будет подключён, пользователь сможет выполнять **функции сайта** через одну строку. Примеры:

- «Добавь задачу купить фильтр.»
- «Запиши 850 рублей продукты.»
- «Покажи расходы за неделю.»
- «Добавь заправку 42 литра на 3000.»
- «Создай заметку...»
- «Что у меня завтра?»

**Те же действия остаются доступными через обычный UI.** Движок — [COMMAND_ENGINE.md](COMMAND_ENGINE.md).

**Что уже работает в прототипе (не весь список выше).** Реализована первая итерация: вопросы о дне,
просроченных задачах, предложениях, расходах и автомобиле, «Что ты умеешь?», а также создание задачи,
создание события, отметка задачи выполненной и перенос задачи. Разбор — детерминированные правила без
AI/LLM и без сети; выполнение — через тот же общий слой действий, поэтому запись попадает в «Историю»
и отменяется обычной кнопкой. Вторая итерация добавила выбор среди нескольких подходящих задач,
продолжение исходной команды и подтверждение однозначного предположения. Временный context не
сохраняется как память, отмена ничего не меняет, stale target и double confirm безопасны. Третья
итерация добавила заметки: создание («Создай заметку …» — весь текст после слова «заметку» становится
содержимым целиком, без переключения на другой домен из-за похожих слов внутри текста) и поиск/показ
уже созданных заметок («Покажи заметки про …», read-only, без записи в «Историю»). Четвёртая итерация
добавила напоминания: создание («Напомни завтра …» — дата обязательна, текст сохраняется целиком) и
поиск/показ уже созданных напоминаний («Покажи напоминания», read-only, без записи в «Историю») через
существующий `AvenNotify`. Изменение, архивирование и удаление уже существующей заметки текстом,
изменение/«отложить»/«скрыть»/удаление уже существующего напоминания текстом, расходы, заправки и
покупки текстом, перенос событий и удаление **пока не поддержаны** — фактический контракт и границы:
[COMMAND_ENGINE.md §9–12](COMMAND_ENGINE.md), слой — [ARCHITECTURE §3.5–3.6](ARCHITECTURE.md).

### 3.3. Голос **[Stage 3, где поддерживается]**

Голос — слой поверх текстового Command Engine: `audio → STT → text → Command Engine`; ответ `result → response text → optional TTS`. Business Logic не связывается непосредственно с Speech Recognition. Сайт остаётся полноценно полезным без голоса ([PROJECT_PLAN.md](PROJECT_PLAN.md), раздел 6.2). Детали — [VOICE.md](VOICE.md).

### 3.4. Пользовательские команды и персональный словарь **[Stage 2]**

Настройки → Aven → Команды и словарь: добавление/отключение/редактирование команд, альтернативные фразы, привязка к Action или Automation Workflow, тестирование распознавания; персональные значения слов («бэха» → BMW 530d). Детали — [COMMAND_ENGINE.md](COMMAND_ENGINE.md), разделы 4–5.

### 3.5. История действий и Undo **[MVP-черновик]**

Пользователь видит, что Aven сделал: «19:42 — добавлен расход; 19:43 — создано напоминание; 19:50 — обновлён пробег». Для подходящих действий предусмотрен Undo. См. [COMMAND_ENGINE.md](COMMAND_ENGINE.md), [UI_UX.md](UI_UX.md).

### 3.6. Suggestions (контекстные подсказки) **[реализовано в UX-прототипе]**

Aven детерминированно предлагает полезное следующее действие по уже существующим локальным данным. Каждая карточка показывает: что замечено, конкретную причину, ожидаемый результат кнопки и способы «Отложить»/«Скрыть». Реализованы правила для задач, календаря/дня, обслуживания авто и гарантий покупок; Home показывает ограниченный top, «День» учитывает выбранную дату, Assistant читает тот же список. Stable IDs, отдельное состояние подавления, History/Undo и автоматическое исчезновение при устранении причины предотвращают спам. Действия над сущностями идут через Common Actions. Это не AI/LLM и не вторая лента уведомлений. «Что ты умеешь?» даёт контекстную справку, а не стену всех возможностей. Примеры — [UI_UX.md](UI_UX.md).

### 3.7. Утро и вечер (режимы) **[реализовано в UX-прототипе]**

Концепция утреннего и вечернего режима: утро — события дня, задачи, важные сроки, напоминания, при доступности — погода, краткий обзор дня; вечер — итоги дня, невыполненные дела, расходы, планирование следующего дня. Понятия «утро», «вечер», «после работы» имеют пользовательские настройки. Детали — [UI_UX.md](UI_UX.md).

**Состояние прототипа (2026-09-27).** Реализованы два пошаговых сценария по уже существующим данным: «Утренний обзор» (`#/morning`, 6 шагов: сводка → ближайшее событие и события дня → задачи на сегодня → просроченное и важные уведомления → предложения → переход в «День») и «Итоги дня» (`#/evening`, 5 шагов: итоги и прошедшие события → выполненное → оставшееся и просроченное → подготовка завтра → завершение). Собственных сущностей нет: сводку считает DOM-free `AvenDaily`, действия (выполнить/вернуть, открыть, перенести на завтра, создать задачу на завтра, действие Suggestion) идут через Common Actions и отменяются в «Истории». «Главная» предлагает подходящий сценарий по времени суток из настроек, «День» даёт прямые кнопки и остаётся рабочим центром даты. Сценарий можно пропустить и вернуться позже; погода и отдельный блок расходов дня в прототип не входят. Фоновых будильников и доставки при закрытой вкладке нет ([ADR-010](DECISIONS.md)).

### 3.8. Настройки (/settings) **[состав для MVP не определён]**

Полная структура категорий настроек — [PROJECT_PLAN.md](PROJECT_PLAN.md), раздел «Настройки Aven»: Профиль; Голос; Поведение Aven; Голосовые события/уведомления; Команды; Персональный словарь; Память; Автоматизации; Модули; Главная; Приватность; Безопасность; Интеграции; Синхронизация; Файлы; Доступность; Экспериментальные функции.

- **Настройки должны работать через UI**; в будущем подходящие настройки можно менять командами (`settings.*` actions — [ADR-011](DECISIONS.md), [PROJECT_PLAN.md](PROJECT_PLAN.md), раздел 12).
- **Разделение**: `/settings` — пользовательские настройки; `/admin` — управление системой ([ADR-012](DECISIONS.md), [ADMIN.md](ADMIN.md)).
- Чувствительные настройки при изменении командой требуют подтверждения и/или повторной аутентификации ([SECURITY.md](SECURITY.md)).

## 4. Напоминания и события

### 4.1. Типы событий

Aven поддерживает события различных типов:

- по точному времени;
- через определённый интервал;
- повторяющиеся;
- за N времени до события;
- по достижению значения;
- в будущем — по геопозиции **[Позже]**;
- в будущем — по событию устройства **[Позже]**;
- в будущем — по внешнему интернет-событию **[Позже]**.

Примеры:

- «Через час нужно быть у врача.»
- «Через 20 минут выключить духовку.»
- «Каждый понедельник в 9 напомни передать показания.»
- «За месяц до окончания страховки предупреди.»
- «На пробеге 120000 напомни про ГРМ.»

### 4.2. Градация важности

- обычное;
- важное;
- критическое / будильник-подобное — насколько позволяет платформа.

## 5. Память Aven

Память **не** является бесконтрольной AI-памятью. Разделы (модель данных — [DATA_MODEL.md](DATA_MODEL.md)):

1. **Профиль**: имя; язык; часовой пояс; валюта; обращение; голос; определение «утро/вечер»; другие предпочтения.
2. **Объекты пользователя**: автомобили; жильё; устройства; проекты; счета; люди; покупки; документы; пользовательские объекты.
3. **Факты**: например, «Основная машина = BMW», «Зимние колёса находятся в гараже».
4. **Структурированная история**: расходы; заправки; ремонты; платежи; пробег; выполненные задачи; события.
5. **Временный контекст диалога**: Aven понимает продолжение контекста («Покажи расходы BMW за сентябрь» → «А за август?» → «А только бензин?») без повторения «BMW».
6. **Пользовательский словарь и команды.**
7. **Сценарии и автоматизации.**
8. **Пользовательские предпочтения поведения Aven.**

Обязательно существует интерфейс **«Память Aven»**, где пользователь может просматривать, редактировать и удалять сохранённую постоянную информацию. Aven **не** сохраняет бесконтрольно каждую произнесённую фразу как постоянную память.

## 10. Автоматизации

- **Готовые автоматизации, простые правила, расписания** — могут существовать на раннем этапе, не дожидаясь Canvas.
- **Automation Canvas** — node-based редактор **[Stage 4]**; реализуется после стабилизации базовых данных и Action Core; срок не утверждён; сложность Canvas не задерживает полезный сайт ([AUTOMATION.md](AUTOMATION.md)).
- **Готовые шаблоны**: Утренний обзор; Вечернее планирование; Контроль расходов; Автомобиль; Страховка; Регулярные платежи; собственные шаблоны в будущем.
- Обычный пользователь не обязан разбираться в Canvas.

## 12. Платформы **[Позже — Stage 5–6]**

Web-first ≠ Web-only: архитектура должна позволять PWA, Android, iOS, desktop, integrations, но они **не являются текущей целью разработки** ([ADR-013](DECISIONS.md), [FUTURE.md](FUTURE.md)). Сначала — полезный и проверенный веб-продукт; затем по реальному использованию определяется набор функций мобильных приложений. Не входят в первый MVP.
