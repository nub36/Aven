# OFFLINE_SYNC — Offline-first / Local-first

> **Статус:** Future / Under Design. Документ **сохраняется**, но с текущим направлением **Web-first** ([ADR-013](DECISIONS.md)) сложная offline-синхронизация **не является обязательным условием запуска первой web-версии**. Offline/local-first — желаемое **будущее** свойство Aven (особенно для мобильных приложений, Stage 5–6). Стратегия разрешения конфликтов не выбрана (см. [PROJECT_PLAN.md](PROJECT_PLAN.md), открытые вопросы).
> **Последнее обновление:** 2026-09-25

---

## 1. Принцип

Offline/local-first остаётся **желаемым будущим свойством** Aven: система должна иметь возможность **частично работать без интернета** ([ADR-007](DECISIONS.md), `Product Principle`); конкретная офлайн/синхронизационная стратегия — **Under Discussion**. При восстановлении интернета — безопасная синхронизация.

**Текущая трактовка приоритета (2026-09-25, владелец):** сложная offline-синхронизация не должна быть обязательным условием запуска первой web-версии. Для Web можно использовать **локальные возможности браузера** там, где это даёт практическую пользу, но **не строить сейчас сложную распределённую sync-систему без подтверждённой необходимости**.

## 2. Доступно без интернета (потенциально) — Future

- заметки;
- задачи;
- локальные события;
- часть календаря;
- расходы;
- авто;
- калькуляторы;
- локальный поиск;
- локально сохранённые файлы;
- часть Command Engine;
- TTS/STT там, где устройство позволяет.

Функции, недоступные офлайн (серверные: синхронизация, часть автоматизаций, серверные интеграции и т.п.), честно помечаются статусом «недоступно офлайн» ([ADR-010](DECISIONS.md)).

## 3. При восстановлении интернета — Future / Under Design

- **безопасная синхронизация**;
- **разрешение конфликтов** (стратегия — открытое решение);
- статус **pending sync** для неотправленных изменений.

## 4. Состояния системы — Under Design

| Состояние | Смысл |
|---|---|
| Online | Полная функциональность |
| Offline | Работа на локальных данных; недоступное честно помечается |
| Sync pending | Есть неотправленные изменения; синхронизация ожидает/выполняется |
| Local/private data | Будущее: данные только на устройстве пользователя, без выгрузки на сервер |

## 5. Клиенты

- **Web (текущая цель):** можно использовать локальные возможности браузера там, где это даёт практическую пользу; хранилище офлайн-данных — не выбрано (IndexedDB / OPFS / SQLite-WASM и т.п. — открытое решение; приоритет понижен до появления подтверждённой необходимости).
- **Мобильные приложения (будущее):** локальная БД SQLite (кандидат, [DECISIONS.md](DECISIONS.md), ADR-104), полная офлайн-модель, синхронизация с сервером.

## 6. Безопасность офлайн-данных

Локальные данные защищаются средствами платформы; приватные данные не покидают устройство без необходимости ([SECURITY.md](SECURITY.md)); будущее состояние «Local/private data» — данные принципиально не покидают устройство.

## 7. Открытые вопросы

1. Стратегия разрешения конфликтов: last-write-wins / CRDT / на базе журнала операций / ручное разрешение — **не выбрана**.
2. Хранилище офлайн-данных в вебе — не выбрано.
3. Объём офлайн-функциональности Command Engine (какие intents доступны локально).
4. Очередь отложенных действий (создано офлайн напоминание → сервер доставит уведомление после синхронизации) — семантика и UX.
5. Индикаторы состояний в UI (детали — [UI_UX.md](UI_UX.md)).
