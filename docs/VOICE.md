# VOICE — Голосовой слой Aven

> **Статус:** проектная документация. Провайдеры STT/TTS не выбраны (см. [PROJECT_PLAN.md](PROJECT_PLAN.md), открытые вопросы).
> **Последнее обновление:** 2026-09-25

---

## 1. Роль голоса

- Пользователь может взаимодействовать **голосом и текстом**.
- **Микрофон НЕ обязателен.** Текстовый ввод всегда доступен ([ADR-003](DECISIONS.md)).
- Ответы могут одновременно показываться текстом и озвучиваться.
- Вся внутренняя система работает с **текстовым представлением команды**.
- **Голос — слой поверх текстового Command Engine (Stage 3)** ([ADR-013](DECISIONS.md)). Не связывать Business Logic непосредственно с Speech Recognition.
- Сайт обязан быть полноценно полезным без голоса: ни одна базовая функция не зависит от микрофона/STT/TTS ([PROJECT_PLAN.md](PROJECT_PLAN.md), раздел 6.2).

## 2. Архитектура голосового пути

```
Voice:   audio → STT → text → Command Engine
Answer:  result → response text → optional TTS
```

Развёрнуто:

```
Микрофон
→ Speech-to-Text
→ текст
→ Command Engine
→ Action
→ Result
→ текстовый ответ
→ Text-to-Speech
```

Голосовой слой **заменяем**: STT/TTS-движки и провайдеры изолированы за интерфейсами и могут быть заменены без изменения ядра.

## 3. Веб-версия

Обязательное UX-правило (см. также [UI_UX.md](UI_UX.md)): **ни одна базовая функция не становится недоступной** только потому, что нет микрофона; пользователь запретил доступ к микрофону; STT не поддерживается браузером; пользователь не хочет разговаривать; TTS отключён. Для базовых функций существует обычный UI.

Рассматриваются системные браузерные возможности:

- **Speech Synthesis API** — для TTS;
- **Web Speech API** — для STT там, где это доступно.

**Важно:**

- Не считать поддержку браузерами гарантированной.
- Предусмотреть **fallback на текст** (ввод и ответ) при отсутствии/отказе голосовых возможностей.
- Платформа не поддерживает голос → честный статус «платформа не поддерживает» ([ADR-010](DECISIONS.md)), функция не изображается работающей.

## 4. Мобильные приложения (будущее)

- Использовать **системные TTS/STT** и/или **локальные движки**.
- Мобильные приложения расширят фоновые возможности (напоминания/озвучивание вне активной сессии браузера).

См. [FUTURE.md](FUTURE.md).

## 5. Настройки голоса

Требуется предусмотреть (категории «Голос» и «Голосовые события/уведомления» — [PROJECT_PLAN.md](PROJECT_PLAN.md), раздел «Настройки Aven»):

- выбор доступного голоса;
- скорость;
- высота (pitch);
- громкость;
- автоматическая озвучка (включение/выключение голосовых ответов);
- повтор последнего ответа;
- голосовой ввод (включение/выключение);
- тест голоса;
- fallback при недоступности STT/TTS;
- язык;
- разрешение голосового произнесения; тихие часы; правила, когда разрешено произнесение;
- уровни важности; повтор; звук перед голосом; поведение при подключённых наушниках;
- правила произнесения приватной информации;
- ограничения платформ отображаются честно ([ADR-010](DECISIONS.md)).

Управление голосовыми настройками доступно и командами (`settings.voice.*`, `settings.quiet_hours.set` — [PROJECT_PLAN.md](PROJECT_PLAN.md), раздел 12; [COMMAND_ENGINE.md](COMMAND_ENGINE.md)); голосовая команда не обходит security requirements.

Хранение настроек — в профиле пользователя ([DATA_MODEL.md](DATA_MODEL.md), «Профиль»).

## 6. Честные ограничения платформ

- **Не обещать**, что закрытый браузер сможет сам произнести голосовое сообщение.
- **Web Push и возможности браузера/ОС имеют ограничения** — фоновое произнесение и фоновые напоминания в вебе ограничены платформой.
- В вебе ограниченные возможности честно помечаются; расширенные фоновые возможности — задача мобильных приложений (будущее).

## 7. Голос и безопасность

- Голосовой ввод проходит тот же конвейер Command Engine, включая confidence и подтверждения опасных действий ([COMMAND_ENGINE.md](COMMAND_ENGINE.md)).
- Распознанный текст показывается пользователю (прозрачность: что именно понял Aven) — см. [UI_UX.md](UI_UX.md).

## 8. Админ-аспекты

Выбор/настройка STT/TTS-провайдеров, языков, дефолтов, fallback и лимитов — в админке ([ADMIN.md](ADMIN.md), раздел Voice).

## 9. Открытые вопросы

1. Конкретные STT/TTS-провайдеры (браузерные / серверные / локальные) — не выбраны. Исследование натурального женского TTS (этап 1, shortlist + образцы для прослушивания) — [TTS_RESEARCH.md](TTS_RESEARCH.md); выбор голоса — за владельцем.
2. Матрица поддержки браузерами (Chrome/Edge/Safari/Firefox, desktop/mobile) — составить на этапе проектирования MVP.
3. Серверный STT (если понадобится): приватность аудио, стоимость, лимиты.
4. Тихие часы: поведение при критических напоминаниях (будильник-подобных) — взаимодействие с настройками важности ([FEATURES.md](FEATURES.md), раздел 4.2).

## 10. Реализация в визуальном прототипе (2026-09-25)

В `/prototype` голос реализован **исключительно средствами браузера**, без AI и без платных API:

- **TTS:** `window.speechSynthesis` / `SpeechSynthesisUtterance` (`prototype/js/voice.js` → `AvenVoice.speak`). Настройки скорости/высоты/громкости/голоса — в «Настройки → Голос»; демо-профиль тембра персонажа — опционально ([CHARACTER.md](CHARACTER.md)).
- **STT (экспериментально):** `SpeechRecognition` / `webkitSpeechRecognition` (`AvenVoice.createRecognizer`) — кнопка 🎤 в Assistant; промежуточный текст, автоотправка (опционально), честные ошибки («нет доступа к микрофону», «речь не распознана»).
- **Честность (ADR-010):** в «Настройки → Голос» отображается реальный статус поддержки браузера (TTS: да/нет, STT: да/нет). При недоступности — всегда текстовый fallback; базовые функции не зависят от голоса (ADR-003).
- **Без авто-озвучки без жеста:** приветствие показывается текстом с кнопкой 🔊 (ограничения autoplay браузеров).
- Это **не** Command Engine и **не** production: распознавание идёт в демо- state machine ([flows.js](../prototype/js/flows.js)), а не в реальный конвейер команд.

### 10.1. Натуральный голос — эксперимент (2026-09-25, [TTS_RESEARCH.md](TTS_RESEARCH.md))

- `speechSynthesis` **сохранён** и остаётся движком по умолчанию и бесплатным fallback.
- `prototype/js/tts/normalize.js` — нормализация текста **только для речи** (время, даты, деньги, км, литры, проценты, словарь «Aven → Авен»); экранный текст не меняется.
- `prototype/js/tts/providers.js` — `SystemTTSProvider` / `NaturalTTSProviderExperimental` + менеджер `AvenTTS` (stop, кэш в памяти вкладки, замер задержки, честный fallback).
- Presence: новое состояние `preparing` — «Готовлю речь…».
- «Настройки → Голос»: движок (Системный / Натуральный · эксперимент), голос, лицензия, self-hosted сервер, приватность (Локально / Онлайн-голос браузера / Self-hosted / Готовые образцы), ▶ Прослушать, ■ Стоп, «Как Aven прочитает текст».
- `prototype/voice-lab.html` — A/B-сравнение образцов (слепой режим, оценки ★); в git — компактный набор 193 MP3 (вариант Б), состав — `research/tts/candidates.json` → `publish`.
- `research/tts/server.py` — исследовательский self-hosted сервер (не production).

### 10.2. Этап 2: фаворит владельца и расширенный тест (2026-09-25, [TTS_RESEARCH.md](TTS_RESEARCH.md) §11–§15)

- **Фаворит владельца на слух:** `qwen3/vd17-design` (Qwen3-TTS-12Hz-1.7B-VoiceDesign, Apache-2.0) — ★5 **предварительно**.
  Это **кандидат, а не обязательная зависимость Aven**: TTS-архитектура не утверждена, решение — за владельцем.
- **System TTS (`speechSynthesis`) сохранён**: движок по умолчанию и рабочий fallback. Голос не внедрялся в Aven
  как обязательный; поведение прототипа для пользователя не изменилось.
- **Расширенный сценарный тест** фаворита: 21 реплика Aven (короткие ответы, напоминания, деньги, авто,
  вопрос, предупреждение, развёрнутый ответ + 4 варианта произношения «Aven/Авен»).
  Фразы — `research/tts/phrases_vd17.json`; образцы — `prototype/assets/voice-samples/qwen3/vd17-design/xNN.mp3`;
  страница прослушивания — **`prototype/voice-lab-vd17.html`** (проигрывание группами, ★ за каждую фразу,
  сравнение с системным голосом). Базовый набор T1–T10 не изменился — сравнимость движков сохранена.
- **Произношение «Авен»** проверяется отдельно: экранный текст «Aven» не меняется, меняется только то,
  что подаётся в TTS (словарь/подсказка). Какой вариант верный — решает владелец на слух (см. §11 отчёта).
- **Практическая скорость:** на CPU Qwen3 непригоден для диалога (20–40 с на фразу — наше измерение);
  на GPU, по опубликованным данным разработчика, первый пакет звука ≈ 97–101 мс, RTF ≈ 0,29–0,46.
  Требования: ≈4,5 ГБ весов (1.7B) / ≈2,5 ГБ (0.6B) → GPU от 8 ГБ (лучше 12 ГБ). Настоящий streaming
  даёт vLLM-Omni (`/v1/audio/speech`, PCM + WebSocket), пакет `qwen-tts` 0.1.1 — нет.
- **Варианты подключения к Web Aven** (самостоятельного утверждения нет): свой GPU-сервер / аренда GPU /
  готовые образцы + кэш; fallback — System TTS. Разбор — §13 отчёта.
- **Lip-sync для будущего 3D:** Qwen3-TTS фонемные тайминги **не** отдаёт (проверено по исходникам пакета);
  план — отдельный шаг forced alignment по готовому аудио (Rhubarb, MIT / MFA, MIT) → визимы → блендшейпы.
  Сейчас ничего из этого не реализовано.

### 10.3. Этап 2.1: произношение «Авен» и способы его исправить (2026-09-25, [TTS_RESEARCH.md](TTS_RESEARCH.md) §16)

- **Проверены способы, которые раньше были только описаны:** перебор орфографии, подсказка о произношении
  в промпте голоса и in-context learning (клоны `0.6B-Base` / `1.7B-Base` по эталонному клипу).
  18 клипов, один CPU-прогон GitHub Actions (run 36184248453), 0 ошибок. Голос **не внедрён**,
  `speechSynthesis` остаётся движком по умолчанию и fallback; ADR не создавался.
- **Добавлена объективная метрика имени** (`name_lwer`): буквы имени вырезаются из гипотезы Whisper по якорям
  и сравниваются с «авен». Она показывает, что прежний вывод «ни один вариант не даёт эталонного «Авен»»
  был артефактом словесного WER: текущий словарь **«Aven → Авен» по буквам точен** (0%), а замены
  («Авин» → «Арин», «Авэн» → «авон», «А́вен» → «айф», прайминг повтором → «Авин») делают хуже.
  **Ударение и паузу ASR не измеряет** — это решает владелец на слух.
- **Лучший объективный результат — естественный контекст:** «Меня зовут Авен.» распознана целиком без ошибок.
  Отсюда практический путь (без GPU и без смены голоса): **готовый образец приветствия** — один удачный клип
  переиспользуется (кэш/готовые реплики), а в коротких ответах («Готово.», «Слушаю.») имя не произносится.
- **Клоны Base:** 0.6B-клон устойчивее на коротких репликах («Слушаю.» — 0% против провала у VoiceDesign)
  и точно говорит «Авен» в развёрнутой фразе; 1.7B-клон по имени хуже («Авент», «Овен»). Тембр клонов
  на слух **не** сравнивался — это следующий шаг владельца.
- **Прослушивание:** `prototype/voice-lab-name.html` — варианты по способам, сравнение шести вариантов одной
  фразы подряд, ★ за каждый вариант, кнопка «Системный голос», таблица «кто как говорит «Авен»» по всем
  прогонам. Ссылки на страницу — из `voice-lab.html` и `voice-lab-vd17.html`.

### 10.4. Natural Voice runtime — связь с реальным сервером (2026-09-26, [TTS_RESEARCH.md](TTS_RESEARCH.md) §17)

- **Причина прошлого «не подключён — HTTP 404»** найдена аудитом: фронт ждёт contract
  `GET {base}/api/tts/health` (ранее `/api/tts/voices`) и `POST {base}/api/tts/synthesize`, а по
  указанному LAN-адресу работал **другой** сервер без этих путей (HTTP 404 = сервер ответил, путь
  не найден; mixed content дал бы `TypeError`, а не код ответа). Плюс структурный разрыв: в самом
  `server.py` Qwen3-движка не было — `vd17-design` не мог на нём появиться.
- **Движок `qwen3/vd17-design` добавлен** в `research/tts/server.py` (env `AVEN_TTS_QWEN3=1`; тот же
  `DESIGN_PROMPT`, что у образцов — иначе тембр «уплывёт»). GPU обязателен (§12 исследования);
  запуск — пошагово в `research/tts/runtime/README.md`. Веса в git не коммитятся.
- **Контракт (§8, согласован с существующим кодом — не второй API):**
  `GET /api/tts/health` → `{ok, status, server, version, engines, voices, uptime_s, max_chars}`;
  `GET /api/tts/voices`; `POST /api/tts/synthesize {text, voice, rate}` → `audio/wav` (PCM 24 кГц —
  играется `<audio>` без перекодирования; на LAN сеть не лимитирует). `text` — уже нормализованный
  для речи; тексты запросов сервер не логирует.
- **Frontend (providers.js):** реальный health-check с честной классификацией причин —
  HTTP-код (404 = «по адресу НЕ Aven TTS server»), timeout, mixed content, сеть/CORS; таймаут синтеза
  (`natural.timeoutSec`, по умолчанию 10 с — здоровый GPU отвечает за доли секунды; для CPU-проверки
  поднять до ~120); presence различает «Говорю · Natural» и «Говорю · системный голос»; fallback-тосты
  «Natural Voice недоступен … — используется системный голос» / «…не ответил вовремя…» — никакого
  имитированного Natural (ADR-010). Stop и прерывание новой речью работают для обоих движков.
- **CORS сервера — контролируемый** (не `*`): `https://nub36.github.io` + localhost, остальные origin —
  `AVEN_TTS_ORIGINS`; preflight Private Network Access поддержан.
- **Статусы честно (§26-style):** Frontend integration ready ✅ · Backend contract ready ✅ (19/19
  HTTP-проверок заглушечной моделью) · Локальная связка «Главная → Natural → состояния/fallback/stop» —
  37/37 jsdom-проверок · **GPU runtime — НЕ запускался** (в песочнице нет GPU, HF заблокирован;
  запуск — на машине владельца по runtime-README) · Public HTTPS demo — нет (GitHub Pages статичен;
  нужен HTTPS endpoint — решение владельца, варианты §13).
