# VOICE — Голосовой слой Aven

> **Статус:** проектная документация. Провайдеры STT/TTS не выбраны (см. [PROJECT_PLAN.md](PROJECT_PLAN.md), открытые вопросы).
> **Последнее обновление:** 2026-09-25

---

## 1. Роль голоса

- Пользователь может взаимодействовать **голосом и текстом**.
- **Микрофон НЕ обязателен.** Текстовый ввод всегда доступен ([ADR-003](DECISIONS.md)).
- Ответы могут одновременно показываться текстом и озвучиваться.
- Вся внутренняя система работает с **текстовым представлением команды**.
- **Голос — слой поверх текстового Command Engine (Stage 3)** ([ADR-013](DECISIONS.md)). Не связывать Business Logic непосредственно с Speech Recognition.
- Сайт обязан быть полноценно полезным без голоса: ни одна базовая функция не зависит от микрофона/STT/TTS ([PROJECT_PLAN.md](PROJECT_PLAN.md), раздел 6.2).

## 2. Архитектура голосового пути

```
Voice:   audio → STT → text → Command Engine
Answer:  result → response text → optional TTS
```

Развёрнуто:

```
Микрофон
→ Speech-to-Text
→ текст
→ Command Engine
→ Action
→ Result
→ текстовый ответ
→ Text-to-Speech
```

Голосовой слой **заменяем**: STT/TTS-движки и провайдеры изолированы за интерфейсами и могут быть заменены без изменения ядра.

## 3. Веб-версия

Обязательное UX-правило (см. также [UI_UX.md](UI_UX.md)): **ни одна базовая функция не становится недоступной** только потому, что нет микрофона; пользователь запретил доступ к микрофону; STT не поддерживается браузером; пользователь не хочет разговаривать; TTS отключён. Для базовых функций существует обычный UI.

Рассматриваются системные браузерные возможности:

- **Speech Synthesis API** — для TTS;
- **Web Speech API** — для STT там, где это доступно.

**Важно:**

- Не считать поддержку браузерами гарантированной.
- Предусмотреть **fallback на текст** (ввод и ответ) при отсутствии/отказе голосовых возможностей.
- Платформа не поддерживает голос → честный статус «платформа не поддерживает» ([ADR-010](DECISIONS.md)), функция не изображается работающей.

## 4. Мобильные приложения (будущее)

- Использовать **системные TTS/STT** и/или **локальные движки**.
- Мобильные приложения расширят фоновые возможности (напоминания/озвучивание вне активной сессии браузера).

См. [FUTURE.md](FUTURE.md).

## 5. Настройки голоса

Требуется предусмотреть (категории «Голос» и «Голосовые события/уведомления» — [PROJECT_PLAN.md](PROJECT_PLAN.md), раздел «Настройки Aven»):

- выбор доступного голоса;
- скорость;
- высота (pitch);
- громкость;
- автоматическая озвучка (включение/выключение голосовых ответов);
- повтор последнего ответа;
- голосовой ввод (включение/выключение);
- тест голоса;
- fallback при недоступности STT/TTS;
- язык;
- разрешение голосового произнесения; тихие часы; правила, когда разрешено произнесение;
- уровни важности; повтор; звук перед голосом; поведение при подключённых наушниках;
- правила произнесения приватной информации;
- ограничения платформ отображаются честно ([ADR-010](DECISIONS.md)).

Управление голосовыми настройками доступно и командами (`settings.voice.*`, `settings.quiet_hours.set` — [PROJECT_PLAN.md](PROJECT_PLAN.md), раздел 12; [COMMAND_ENGINE.md](COMMAND_ENGINE.md)); голосовая команда не обходит security requirements.

Хранение настроек — в профиле пользователя ([DATA_MODEL.md](DATA_MODEL.md), «Профиль»).

## 6. Честные ограничения платформ

- **Не обещать**, что закрытый браузер сможет сам произнести голосовое сообщение.
- **Web Push и возможности браузера/ОС имеют ограничения** — фоновое произнесение и фоновые напоминания в вебе ограничены платформой.
- В вебе ограниченные возможности честно помечаются; расширенные фоновые возможности — задача мобильных приложений (будущее).

## 7. Голос и безопасность

- Голосовой ввод проходит тот же конвейер Command Engine, включая confidence и подтверждения опасных действий ([COMMAND_ENGINE.md](COMMAND_ENGINE.md)).
- Распознанный текст показывается пользователю (прозрачность: что именно понял Aven) — см. [UI_UX.md](UI_UX.md).

## 8. Админ-аспекты

Выбор/настройка STT/TTS-провайдеров, языков, дефолтов, fallback и лимитов — в админке ([ADMIN.md](ADMIN.md), раздел Voice).

## 9. Открытые вопросы

1. Конкретные STT/TTS-провайдеры (браузерные / серверные / локальные) — не выбраны.
2. Матрица поддержки браузерами (Chrome/Edge/Safari/Firefox, desktop/mobile) — составить на этапе проектирования MVP.
3. Серверный STT (если понадобится): приватность аудио, стоимость, лимиты.
4. Тихие часы: поведение при критических напоминаниях (будильник-подобных) — взаимодействие с настройками важности ([FEATURES.md](FEATURES.md), раздел 4.2).
