## 2. Почему single-image-to-3D в принципе не даёт нужного результата

Любой метод «одно фото → меш» (TripoSR, а также более качественные TRELLIS/Hunyuan3D)
**архитектурно не выдаёт**:

- **rig** (скелет head/neck/jaw/eyes) — на выходе только статичный меш;
- **отдельную геометрию глаз, веки, зубы, язык, jaw** — всё «слипается» в один меш;
- **facial blendshapes / ARKit / visemes** — их неоткуда взять из одной картинки;
- **чистую топологию под анимацию** — выходит «суп» из треугольников, не edge-loops лица;
- **волосы как отдельный управляемый слой** — волосы запекаются в общий меш «шапкой».

Более новые модели (раздел 3.1) улучшают **геометрию и текстуру статичного бюста**, но
**не решают** ни одну из проблем выше. Поэтому путь к анимируемой Female Aven — это не
«лучшая image-to-3D модель», а **топология с ригом от digital-human пайплайна** (раздел 3.3)
или **base mesh + ручная работа художника** (раздел 3.4), в которые identity вносится по
reference-видам.

## 3. Исследование реальных pipeline (4 сильных кандидата)

Для каждого: бесплатность/лицензия/коммерческое использование, ОС, CPU/GPU, запускаемость в
нашей инфраструктуре, качество лица, сохранение identity, наличие topology/rig/blendshapes,
продолжение в Blender.

### 3.1. Кандидат A — Современные image-to-3D (TRELLIS 2 / Hunyuan3D 2.1)

| Критерий | TRELLIS 2 (Microsoft) | Hunyuan3D 2.1 (Tencent) |
|---|---|---|
| Что даёт | image → mesh + PBR (до 4K), GLB/OBJ/PLY | image → mesh + PBR (albedo/normal/rough/metal) |
| Лицензия | **MIT** (коммерческое без ограничений; пара render-сабмодулей — иная лицензия, нужен аудит) | Tencent Community: коммерческое **с условиями**, **исключает EU/UK/Ю.Корею**, гейт 1M MAU, запрет на обучение чужих моделей |
| ОС | Linux/CUDA (Windows офиц. не поддержан) | Linux/CUDA, Python 3.10 |
| Железо | **16–24 GB VRAM** GPU | **10 GB (shape) … ~29 GB (full)** VRAM GPU |
| Запуск у нас | **Нет** (нет GPU ни в песочнице, ни в бесплатных Actions) | **Нет** |
| Качество бюста | Высокое (лучшая геометрия среди open) | Высокое (лучшие текстуры) |
| Identity | Лучше TripoSR, но всё равно «на глаз» по одному фото | То же |
| topology/rig/blendshapes | **Нет rig, нет blendshapes, нет отдельных глаз** | **То же** |
| Blender дальше | Импорт GLB ок, но это статичный меш → всё равно ретопо+риг вручную | То же |

**Вывод:** качественнее TripoSR как *статичный* бюст, но (1) требует GPU, которого нет в нашей
бесплатной инфраструктуре; (2) **не решает** rig/глаза/веки/jaw/blendshapes; (3) identity
всё равно приблизительная. Как «основа V2 с ригом» — **не подходит**. Может быть полезен позже
как источник высокодетального static-меша/нормалей для художника, если появится GPU.
Источники: сравнения open image-to-3D 2026. citeturn0turn4turn5

### 3.2. Кандидат B — FLAME-семейство (DECA / EMOCA / MICA / SMIRK)

- **Что даёт:** параметрическую реконструкцию лица в топологии **FLAME** — а у FLAME есть
  **articulated jaw, шея, глазные яблоки, регион век, expression-blendshapes**. Это как раз
  анимируемая топология с ригом лица — по смыслу ближе всего к нашей цели.
- **Критический блокер — лицензии для коммерческого продукта (Aven коммерческий):**
  - Базовая **FLAME** (старые версии) и **MICA/DECA/EMOCA/INFERNO** — **только
    non-commercial scientific research**; коммерческое использование, включая инкорпорацию в
    продукт/сервис, **прямо запрещено**. citeturn0search3turn0search8turn0search5
  - Есть **FLAME 2023 Open** под **CC-BY-4.0** (коммерческое разрешено) — но это только
    *базовая модель*, а **предсказатели identity из фото (MICA/DECA/EMOCA) остаются
    non-commercial**. То есть «получить лицо Aven из фото» этими сетями для коммерческого
    продукта **нельзя**. citeturn0search9
- **Железо/ОС:** PyTorch + GPU; у нас **не запускается**.
- **Покрытие:** только лицо/голова (без причёски, уши грубые, без плеч), FLAME expression-
  пространство ≠ ARKit (нужна конвертация).
- **Вывод:** технически самый «правильный по топологии», но **запрещён лицензией** для нашего
  коммерческого продукта и **не запускается** в нашей инфраструктуре. **Не используем.**

шею — то есть всю Stage-3 структуру. Похожесть на reference достигается фитом по утверждённому
фронтальному reference (+ доп. виды, если владелец их одобрит).

разрешает использование в **не-Unreal** движках (наш случай — three.js/WebGL) при выручке
**< $1M** и с запретом обучать на них AI-модели.

**Вывод:** **MetaHuman-путь — сильнейший бесплатный production-путь** (даёт ровно Stage-3 риг),
но требует **Windows + GPU + Unreal** и **ручной работы**, и **не запускается** в этой сессии.
Это основа рекомендации в разделе 7. Identity в MetaHuman вносится через голову-меш, которую
нужно получить из reference (FaceBuilder/скульпт/фотограмметрия по нашим turnaround-видам).

### 3.4. Кандидат D — Free base mesh (CC0) + ручной Blender-художник

- **MPFB 2 / MakeHuman:** ассеты **CC0** (коммерческое, включая закрытые продукты, разрешено),
  Blender-native, параметрический человек, авто-риг (Rigify), morph targets, экспорт в любой
  формат Blender (в т.ч. GLB). Реализм средний, лицо **generic** → нужен скульпт под reference.
  citeturn2search3turn2search4
- **Microsoft RocketBox:** MIT, готовые люди с ARKit+Oculus, но не наша identity, нужен ре-риг.
- **Путь:** взять CC0 female-базу (MPFB) с ригом/ARKit → художник скульптит лицо по нашим
  turnaround-видам → hair cards под Hair A/Color B → PBR-материалы → экспорт GLB.
- **Вывод:** **полностью чистый по лицензии и бесплатный**, всё в Blender; но качество/identity
  **зависят от художника** (не автоматизируется). Хорош как **бесплатная альтернатива**
  MetaHuman, если важна максимальная лицензионная чистота и контроль топологии.

## 4. Дополнительные reference views (Stage 2) — сделано и оценено

**Нужны ли доп. виды?** Да. Любой сильный pipeline (MetaHuman-фит, FaceBuilder multi-view,
скульпт художника) заметно выигрывает от turnaround, а не одного фронтального фото: профиль
задаёт проекцию носа/подбородка/лба, 3/4 — скулы и переход к ушам, back/hair — объём причёски.

**Можно ли получить их безопасно, без смены identity?** Проведена эмпирическая попытка. Из
утверждённого фронтального reference (как **входного изображения**, не «по мотивам») получены
кандидатные виды image-edit-моделью с жёсткой инструкцией «тот же человек, та же причёска/
макияж/одежда/фон/свет, только поворот камеры». **Сохранение identity этим НЕ доказано** —
результат подлежит проверке владельцем (см. ниже):

- `candidate-left-34.jpg` — 3/4 слева;
- `candidate-left-profile.jpg` — левый профиль;
- `candidate-right-34.jpg` — 3/4 справа;
- `candidate-right-profile.jpg` — правый профиль;
- `candidate-back-hair.jpg` — вид сзади (объём/длина волос).

Файлы: `review/3d-v2-reference-views/` и (для web-просмотра) `prototype/assets/character/
v2-reference-views/`. Front — тот же утверждённый master. Дополнительно для оценки собраны
(только crop/resize/компоновка существующих файлов, без генерации): `contact-sheet.jpg`
(reference в центре, 5 видов вокруг) и `face-comparison.jpg` (одинаково масштабированные crop
лиц). Скрипт сборки: `research/3d/build_v2_review_sheets.sh`.

**Статус видов: AI-generated candidate reference views — Under Review.** Субъективно виды
выглядят близко к reference (впечатление агента), но это **НЕ доказательство** и **НЕ
утверждение**, что «это точно один и тот же человек». Сходство identity **не подтверждено**.

**Границы честности (важно):**

- Это **AI-экстраполяция**, а не фотограмметрический захват реального человека. Возможны как
  мелкие расхождения на невидимых деталях (ухо, затылок, линия волос у корней), так и
  **сдвиги черт лица**, которые внешне неочевидны, но меняют identity.
- Поэтому виды имеют статус **Under Review** (не canonical). **Решение — за владельцем**
  (см. страницу оценки `prototype/aven-3d-v2.html`, блок «Решение владельца»).
- В production их можно использовать как guidance/вход в multi-view фит **только если владелец
  одобрит**; в любом случае **фронтальный master остаётся приоритетным источником лица**.

**Если владелец сочтёт сходство недостаточным** — что должен подготовить человек/3D-художник:
консистентный turnaround **одного** рендера/модели (не новые генерации лица): front (нейтраль,
взгляд в камеру, рот закрыт), left/right 45°, left/right profile (90°), back/hair, плюс, если
возможно, вид с макушки (парт-линия) — все с **одинаковым** нейтральным светом и без сильных
теней на лице.

## 5. Целевая структура Female Aven V2 (Stage 3) — требования к результату

Это спецификация, которой должен соответствовать будущий V2 (для MetaHuman/художника):

- **Композиция:** бюст — head + **полная шея** + плечи/верх груди. Полного тела нет.
- **Формат:** GLB/GLTF (встроенные или рядом текстуры), Y-up, метры.
- **SKELETON / RIG:** `head`, `neck`, `jaw`, `eyeLeft`, `eyeRight` (управление взглядом).
- **EYES:** отдельная геометрия глазных яблок; поворот по gaze-таргету.
- **EYELIDS:** `blinkLeft`, `blinkRight` (нормальное моргание, раздельно).
- **FACE blendshapes:** предпочтительно **ARKit-совместимые (полные 52)**. Минимум:
  `jawOpen`, `mouthClose`, `smileLeft`(mouthSmileLeft), `smileRight`(mouthSmileRight),
  `browUp`(browInnerUp/browOuterUp), `browDown`(browDownLeft/Right), основные движения губ
  (`mouthFunnel`, `mouthPucker`, `mouthPress`, `jawLeft/Right`), плюс blink-шейпы выше.
- **VISEMES (минимум, с маппингом на ARKit/шейпы):** REST, A, E, I, O, U, M/B/P, F/V.
  (Маппинг: A→jawOpen; O/U→mouthFunnel/Pucker; M/B/P→mouthClose+jawClose; F/V→нижняя губа к
  верхним зубам (mouthPress/mouthRollLower); E/I→mouthSmile+лёгкий jawOpen; REST→нейтраль.)
- **ВОЛОСЫ:** Hair A / Color B, для realtime — **hair cards / optimized mesh** (НЕ strand-груминг,
  непригодный для WebGL); отдельный меш/материал с alpha.
- **МАТЕРИАЛЫ (PBR):** skin (base/normal/roughness, лёгкий SSS-приём допустим), eyes
  (роговица/склера/радужка), hair (anisotropic/alpha), clothing (charcoal + violet-blue).
  Тёмные волосы/одежда должны читаться в light и dark UI (нейтральный studio-свет как в
  текущем viewer).
- **REALTIME-бюджет (ориентир):** ~**30k–100k** треугольников на основную модель; текстуры
  преимущественно **2K**. Не многомиллионный меш как финальный web-asset.
- **Совместимость с будущими состояниями** (idle/listening/thinking/speaking/success/important/
  waiting/error) и с будущим lip-sync от Aigul — обеспечивается наличием rig + blink + jaw +
  visemes (программировать все состояния сейчас не требуется; важно, чтобы риг это позволял).

## 7. Production-план: путь к качественной Female Aven V2

### 7.1. Что можно автоматизировать, а что требует человека (Stage 4, Blender)

**Можно автоматизировать (Blender Python / скрипты):**

- import GLB/OBJ/FBX; батч-очистка (merge by distance, пересчёт нормалей, удаление мусора);
- **децимация/подгонка бюджета** (как уже сделано в `research/3d/postprocess_bust.py` для V1);
- перенос/переименование shape keys в **ARKit-именование**; проверка наличия обязательных
  blendshapes и bones; генерация visemes-маппинга;
- назначение PBR-материалов по конвенции имён; упаковка/ресайз текстур до 2K;
- **экспорт GLB** (Draco-сжатие) + генерация `stats.json` (polys/verts/textures/bones/morphs);
- автоматические QC-рендеры (турнтейбл) для страницы оценки.

**Требует ручной работы 3D-художника (НЕ автоматизируется честно):**

- **скульпт/фит лица под identity** по reference-видам (главный источник качества и сходства);
- **ретопология** под чистые edge-loops лица (если базовая топология не подходит);
- художественная **укладка hair cards** под Hair A и настройка прозрачности/анизотропии;
- финальная подгонка **век/глаз/jaw**, коррекция корректирующих шейпов, чистка артефактов;
- художественная настройка **skin PBR/SSS** и одежды под бренд.

Граница честная: **скрипт не создаёт identity-preserving голову сам** — он готовит, чистит,
риг-переносит, экспортирует и проверяет. Качество лица даёт художник + фит-инструмент.

### 7.2. Рекомендуемый маршрут A (основной) — MetaHuman

1. **Reference:** утвердить turnaround из раздела 4 (или получить художественный turnaround).
2. **Голова-меш с identity:** на Windows-ПК с GPU — KeenTools FaceBuilder (multi-view фит по
   turnaround; платный триал/подписка) **или** ручной скульпт по видам в Blender/ZBrush.
3. **Mesh to MetaHuman** (UE5, бесплатно): конформ головы → MetaHuman с **ARKit-52**, отдельными
   глазами/зубами, веками, jaw, шеей; подобрать грум под Hair A/Color B.
4. **Экспорт в web-GLB:** UE→Blender→GLB со всеми ARKit-blendshapes (Draco), бюджет 30–100k tris,
   текстуры 2K (пайплайн доказан сообществом). citeturn1search4turn1search1
5. **Blender-автоматизация (наши скрипты):** проверка bones/morphs, ARKit-именование, visemes-
   маппинг, PBR, `stats.json`, QC-рендеры.
6. **Оценка владельцем** на `aven-3d-v2.html` → только после «принимаю» двигаемся дальше.

Лицензия: MetaHuman в не-Unreal движке при выручке <$1M, без обучения AI-моделей на ассетах.
citeturn1search0

### 7.3. Рекомендуемый маршрут B (запасной, максимально чистый по лицензии) — MPFB CC0

1. CC0 female-база из **MPFB 2** (Blender) с ригом (Rigify) и morph-каркасом.
2. Художник скульптит лицо под turnaround; hair cards под Hair A/Color B.
3. Ручная сборка ARKit-blendshapes (можно опираться на публично документированные ARKit-формы
   как на **описание целей**, не копируя чужие меши), blink/jaw/visemes.
4. PBR-материалы; экспорт GLB (наши скрипты); QC; оценка владельцем.

Лицензия: ассеты MPFB/MakeHuman — **CC0** (коммерческое разрешено). citeturn2search3

### 7.4. Что нужно от владельца для старта production

- Решение по turnaround (раздел 4): принять кандидатные виды / заказать художественные.
- Доступ к Windows-ПК с GPU (для MetaHuman/UE или FaceBuilder) **или** привлечение 3D-художника
  с Blender/ZBrush (для маршрута MPFB).
- Подтверждение допустимости лицензии MetaHuman (<$1M, не-Unreal, без AI-train) **или** выбор
  полностью-CC0 маршрута MPFB.

## 8. Aigul + будущий lip-sync (не реализуем сейчас)

Голос **Silero ru_aigul** работает и не трогается. Будущая схема: Aigul audio → анализ →
phoneme/viseme timings → blendshapes Female Aven. Silero может не отдавать timestamps — это не
блокер текущего этапа. Полный lip-sync **не реализуется**, пока нет качественной модели с jaw/
visemes. Что нужно до полноценного lip-sync: (1) утверждённая V2 с ARKit/visemes ригом;
(2) слой выравнивания аудио→виземы (уровень 1 — G2P ru из текста; уровень 2 — Rhubarb/MFA по
аудио, см. [TTS_RESEARCH.md](TTS_RESEARCH.md) §14).
